基线：当前 `0.6.5` 分支上的 v0.6.5 r2 工作树。本文只记录 fix1 的设计结论、实施清单与验收标准；创建本文时不修改产品代码、不重新构建、不重新部署。

## 目标与边界

- 参数 Flyout 打开时必须一次显示全部可见列，不能只禁用横向滚动却仍裁掉右侧列。
- 重新核实四个 residual 精调参数的方向、顺序与字段映射，避免“滑块方向反了”或 Saturation/Lightness 串线。
- 为过长参数标签提供明确换行，不依赖不同 DPI 下的偶然自动折行。
- 取消 `NR Preset` 的参数暴露。
- 将 `NR Intensity`、`Local Tone Strength`、`Local Structure Strength` 收紧到 `0–1`。
- 将 DLSS SR 和 DLSS FG 的 `Use Motion Vectors` 从数值滑块改为与 DLSSNR 相同的开关。
- 不恢复深度估算；Depth 继续使用 r1/r2 已确定的 Zero Depth 合同。

## 已核实的现状与设计结论

### 参数列

- 当前 XAML 已禁用外层 `ScrollViewer` 的水平滚动，但 `FlyoutPresenter` 只设置了 `MaxHeight=650`，没有按可见分组数设置所需宽度，也没有解除/覆盖 Presenter 的默认宽度约束。
- 每列仍固定为 `260px`，列间距为 `16px`。仅依赖 `ItemsControl` 的 DesiredSize 穿过 `ScrollViewer` 和默认 `FlyoutPresenter` 自动扩宽并不可靠，这与“仍未完全展开”的实测现象一致。
- fix1 不能用恢复水平滚动作为回退；应让 Presenter、根内容和列容器共享同一个可验证的目标宽度，并在屏幕可用宽度不足时等比例压缩列宽、换行标签，仍同时保留所有列。

### Residual 的符号与 HSL 映射

- 原始 residual 定义保持为：

  ```text
  rawResidual = reducedDenoised - reducedInput
  ```

- 因此 `rawResidual < 0` 是 DLSSNR 让对应 RGB 分量变暗的变化，`rawResidual > 0` 是让对应分量变亮的变化。乘以 `0/1/2` 应分别表示移除、保持、放大同方向变化，不应额外取负数或使用 `2 - value` 反向。
- 当前参数链路的字段没有接反：
  - `residualSaturation` 从配置进入 `DLSSNRSettings::residualSaturation`，再进入 cbuffer 的 `ResidualSaturation`，最终修改 HSL 的 `.y`（Saturation）。
  - `residualLightness` 从配置进入 `DLSSNRSettings::residualLightness`，再进入 cbuffer 的 `ResidualLightness`，最终修改 HSL 的 `.z`（Lightness）。
- “看起来反向”可能来自 residual 参数的相对语义。例如 DLSSNR 本身降低了饱和度时，将 `Residual Saturation` 从 `1` 调到 `2` 会进一步降低饱和度；这是放大 DLSSNR 的负饱和度变化，不是把画面绝对饱和度调高。fix1 保留这一语义，并在文档中明确说明。
- 当前实现先做 HSL 重建，再按重建后的 RGB 正负值执行 Shadow/Reflection 分段。这样 HSL 转换新产生的正负 RGB 分量会被重新分类，不能严格对应用户指定的原始差值 `0–127 / 128–255` 区间。
- fix1 将运算顺序调整为“原始有符号 residual 分段在前，HSL 差值控制在后”：

  ```text
  scaledResidual = rawResidual * ResidualMultiplier

  signedResidual =
      min(scaledResidual, 0) * ShadowStructureControl +
      max(scaledResidual, 0) * ReflectionGlowControl

  candidateRGB = saturate(originalRGB + signedResidual)
  originalHSL = RGBToHSL(originalRGB)
  candidateHSL = RGBToHSL(candidateRGB)

  candidateHSL.s = saturate(
      originalHSL.s +
      (candidateHSL.s - originalHSL.s) * ResidualSaturation)
  candidateHSL.l = saturate(
      originalHSL.l +
      (candidateHSL.l - originalHSL.l) * ResidualLightness)

  outputRGB = HSLToRGB(candidateHSL)
  ```

- Hue 继续取 `candidateHSL.h`；Alpha 继续取原图 Alpha。四项精调均为 `1` 时必须走旧的精确快速路径，结果保持 `saturate(original + rawResidual * ResidualMultiplier)`，不引入 RGB/HSL 往返误差。

## B. Residual 精调逻辑修正

### B1. 运算顺序

- [x] 将 Shadow/Structure 与 Reflection/Glow 的正负拆分从“HSL 重建后 residual”移动到 `rawResidual * ResidualMultiplier` 之后、HSL 转换之前。
- [x] 保持逐 RGB 分量的有符号拆分；不把原图绝对亮度当作分区条件，也不先量化为 8-bit。
- [x] 不对四个倍率取负、不交换正负分支、不使用反向滑块公式；统一维持 `0=移除变化、1=保持变化、2=同方向放大变化`。
- [x] 保持默认快速路径：四项精调全为 `1` 时绕过 HSL 与额外正负分段，逐像素等价于 r2 当前默认输出。
- [x] 正常 DLSSNR 输出、输入分辨率为 100% 的 residual 路径和 native disabled/pass-through 回退路径使用同一套新顺序；零 residual 时任何组合都不得改变原图。

### B2. Saturation/Lightness 防串线验证

- [x] 增加纯饱和度变化测试向量：候选图仅改变 HSL S，确认只移动 `Residual Saturation` 时 L 不变，`Residual Lightness` 不响应。
- [x] 增加纯明度变化测试向量：候选图仅改变 HSL L，确认只移动 `Residual Lightness` 时 S 不变，`Residual Saturation` 不响应。
- [x] 增加正向和负向变化：DLSSNR 增加/降低饱和度、增亮/压暗各覆盖 `0/1/2`，确认倍率始终缩放变化幅度而非绝对 S/L。
- [x] 增加混合 RGB 符号 residual，确认 Shadow/Structure 只处理原始负分量，Reflection/Glow 只处理原始正分量；HSL 后续调整不改变这个分类依据。
- [x] 覆盖灰色、近零饱和度、接近黑/白、Hue 环绕和裁切边界，确保无 NaN、色相跳变、反相或闪烁。
- [ ] 在日志/调试构建中核对 cbuffer 偏移与字段值，明确证明 Saturation、Lightness、Shadow、Reflection 四项没有错位。

### B3. 用户语义和文档
