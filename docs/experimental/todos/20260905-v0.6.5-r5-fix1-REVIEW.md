# 0.6.5 r5 fix1：实时参数保存 review

本轮按用户要求统一图标、去掉保存按钮、改为自动保存并覆盖部署到 `r5 local`。实机操作和 GPU 测试由用户进行，以下区分已修复缺陷与待用户决定的后续工作。

## 已修复

1. 首页“效果参数”图标从 `F8AA` 改为工具栏实际使用的 `E9E9`。
2. 保存成功后，旧 `_HandleEffectParametersRequest` 使用无参数的 `ResourceLoader::GetForViewIndependentUse()`，而应用的资源树为 `Magpie/Resources`。在旧包实际 PRI 上的独立无界面程序中，默认查找抛出 `0x80073B1F`，指定资源树成功读取原保存提示。旧 UI Dispatcher 回调没有捕获该异常，且这段代码恰在文件写入成功之后执行。fix1 移除了这条保存提示调用，并在参数请求的调度及处理边界捕获异常，保存结果通过独立共享状态返回面板。
3. 移除“保存”按钮。每次实际编辑立即提交设置更新；停止编辑 300 ms 后写盘，持续拖动时约每秒写盘，减少高频磁盘操作。后台只写固定 JSON，沿用 r5 的原子替换和有效备份。只有写盘完成才显示“修改已自动保存”，失败显示失败状态。
4. 去掉“已有一个请求就丢弃后来请求”的全局开关。自动保存合并待写状态，按修订号返回完成结果；旧操作的迟到结果不能覆盖新操作。关闭面板不取消已提交修改；停止缩放仍允许保存先前的修改，退出时再同步保存，等待先前写盘完成。
5. 不再清空并覆盖整条效果链的所有参数：只合并本次确实改动的参数，保留主窗口对其他参数的改动。若同一参数在两处发生冲突，或模式名称、索引处的效果链、缩放类型/尺寸发生变化，拒绝覆盖并提示冲突；冲突后需重新开始缩放以获取新的基准。
6. 保存状态与“需要重新缩放”状态分开。`Live` 项自动保存且实时应用；`Restart` 项自动保存后仍等待“应用并重新缩放”。保留恢复操作并明确命名为“恢复本次缩放初始值”，恢复操作本身也自动保存。
7. Live / Restart 分类使用当前已经初始化的后端能力。旧面板曾用尚未应用的 DLSSNR 输入分辨率开关草稿重新分类，可能停止发送本来能实时生效的残差修改，同时又不计入待重启数量；现已统一。

## 后续建议：本轮未修改，供用户选择

### 1. 优先：自动重建缩放会话时继承已应用的实时参数

- 代码：`Renderer.cpp` 的 `_ApplyPendingEffectParameters` 只更新后端 `_runtimeEffectOptions`；`ScalingWindow.cpp` 的 `ToggleScaling` / `RestartAfterSrcRepositioned` 仍使用原 `_options` 重新启动。
- 触发：调节 Live 参数后切换全屏/窗口模式，或触发需要重新创建渲染器的窗口调整。
- 影响：这些内部重建可能回到本次会话启动时的参数，而磁盘配置已经是新值，出现画面和设置不一致。显式“应用并重新缩放”走的另一条路径已使用合并后的配置。
- 建议：为自动重建维护独立的“当前已应用参数”快照。应明确 Restart 草稿是否随自动重建一起生效，避免不经用户选择就应用尚待重启的设置。

### 2. 优先：后端拒绝 Live 修改时，把结果回传到对应控件

- 代码：`Renderer.cpp` 的 `_ApplyPendingEffectParameters` 在 ApplyLiveParameters / UpdateParameters 失败时保留旧 `_runtimeEffectOptions`，但只发通用提示；面板草稿不随失败回滚。
- 触发：GPU 资源更新失败、后端拒绝某组实时参数。
- 影响：滑块、自动保存的目标设置和实际生效值可能不同；“已保存”只能证明写盘成功，不能证明 GPU 已接受。
- 建议：回传每个参数的成功值与版本号，保留用户目标值但明确标记“未生效”，或在失败时恢复滑块。回传必须校验会话，避免旧后端结果影响新会话。

### 3. 建议：主窗口参数编辑器与工具栏面板同步显示

- 代码：`EffectParametersViewModel` 构造时把值复制到各 `ScalingModeParameter::_value`；`ScalingModeEffectItem` 持有这个 ViewModel；现有 `ScalingModesService` 只有增删移动/重置事件，没有参数变更通知。
- 触发：先打开主窗口参数页，再在工具栏调整同一模式。
- 影响：已经存在的主窗口控件可能仍显示旧值。fix1 的参数合并可保留未触碰的值，但不会刷新旧控件显示。
- 建议：增加按模式、效果、参数区分的通知，避免回写循环。可同时把参数控件的裸 `this` 事件订阅改成弱引用，改善控件与 ViewModel 销毁先后不一致时的生命周期保护；后者目前是审查发现的风险，未复现崩溃。

### 4. 建议：浮点滑块的手工输入使用实际参数值

- 代码：`OverlayDrawer::_DrawEffectParameters` 使用 `ImGui::SliderInt` 编辑离散刻度 `currentTick`，显示格式则是格式化后的浮点值，且未禁用临时文本输入。
- 触发：Ctrl+单击等方式进入 ImGui 滑块手工输入，输入例如 `0.7`。
- 影响：编辑的底层是整数刻度，输入未必按实际参数值解释，可能跳到错误数值。
- 建议：提供按真实浮点/整数参数值解析的输入框，再统一量化到合法步长；或暂时禁用此入口，保留拖动和键盘步进。
