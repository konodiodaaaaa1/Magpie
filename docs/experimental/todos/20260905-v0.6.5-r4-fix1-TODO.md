## 1. 现场症状

1. 打开效果器相关下拉菜单后，用户没有看到预期的“光流质量”选择。
2. 使用 `DLSSNR\DLSSNR_AI_Filter`，并将运动向量质量设为 `High Quality` 后开始缩放。
3. DLSSNR NGX Feature 18 创建成功，随后 Frame Guidance 的 NVOF 提供器初始化失败。
4. Magpie 先产生缩放错误码 `18`，随后进程以访问冲突退出。

本次现场环境：

- GPU：NVIDIA GeForce RTX 5070 Ti，VendorId `0x10DE`，DeviceId `0x2C05`。
- OS：Windows `10.0.26200`。
- 捕获尺寸：`1924 × 1177`。
- 输出尺寸：`2560 × 1440`。
- 捕获方式：Graphics Capture。
- DLSSNR 参数：`enableInputResolutionScaling=1`、`motionVectorQuality=4`。

## 2. 已确认的事实

### 2.1 参数和部署文件没有丢失

部署目录中的 DLSS SR、DLSSFG、DLSSNR、XeSSFG 效果文件都包含 Choice 元数据。现场配置也已保存：

```text
DLSSFG.motionVectorQuality              = 2
DLSSNR.motionVectorQuality              = 4
XeSSFG.opticalFlowMethod                = 0
XeSSFG.amdOpticalFlowMode               = 1
XeSSFG.nvidiaOpticalFlowQuality         = 2
```

运行日志明确打印并消费了 `motionVectorQuality=4`，因此此次问题不是 Choice 解析失败、效果文件漏部署或参数未进入运行时。

### 2.2 DLSSNR 本体创建成功

日志在失败前已经打印：

```text
DLSSNR STATUS: Feature=18 created=true path=signed-snippet ...
motionVectorQuality=4
```

因此不得把本次故障归因于“DLSSNR SDK 不支持 RTX 5070 Ti”或“DLSSNR Feature 创建失败”。失败发生在其后的 NVOF Frame Guidance 初始化阶段。

### 2.3 NVOF 输出纹理创建失败

连续两个 `CreateTexture2D` 调用返回：

```text
HRESULT: 0x80070057  // E_INVALIDARG
```

失败的两个资源与 `NvidiaOpticalFlowProvider::CreateTextures` 中的稠密运动矢量、置信度输出一一对应：

```cpp
constexpr UINT GUIDE_BIND =
    D3D11_BIND_SHADER_RESOURCE | D3D11_BIND_UNORDERED_ACCESS;
constexpr UINT GUIDE_MISC = D3D11_RESOURCE_MISC_SHARED_NTHANDLE;
```

当前 NVOF 路径只设置 `D3D11_RESOURCE_MISC_SHARED_NTHANDLE`。同一设备、尺寸和格式体系下，现有 Zero Frame Guidance/Adapter 路径使用：

```cpp
D3D11_RESOURCE_MISC_SHARED |
D3D11_RESOURCE_MISC_SHARED_NTHANDLE
```

后者在本次运行中创建成功。Frame Guidance D3D11→D3D12 路径后续还会调用 `IDXGIResource1::CreateSharedHandle` 和 `ID3D12Device::OpenSharedHandle`，所以这些输出必须满足完整的 NT shared-resource 合同。

微软文档建议需要 keyed-mutex 同步时使用 `SHARED_NTHANDLE | SHARED_KEYEDMUTEX`。当前 Frame Guidance 由 D3D12 fence 管理消费者生命周期；fix1 不应在没有完整 Acquire/Release 设计的情况下只添加 keyed mutex。

参考：

- [D3D11_RESOURCE_MISC_FLAG](https://learn.microsoft.com/windows/win32/api/d3d11/ne-d3d11-d3d11_resource_misc_flag)
- [ID3D11Device1::OpenSharedResource1](https://learn.microsoft.com/windows/win32/api/d3d11_1/nf-d3d11_1-id3d11device1-opensharedresource1)

### 2.4 错误处理路径又触发空指针

崩溃转储记录：

```text
ExceptionCode:    0xC0000005
Fault RVA:        0x001ABBDC
Access type:      read
Access address:   0x000000000000005A
```

故障指令在基址寄存器为 `nullptr` 时读取偏移 `0x5A`。这说明 NVOF 初始化失败本应返回错误提示，但部分初始化对象的停止/销毁路径又访问了已经为空或尚未建立的对象。

日志还显示第一次启动缩放约一秒后、Renderer 仍在初始化时，又收到一次 `Scale` 热键。当前 `ScalingRuntime` 在进入 `_StartImpl` 前就发布 `Scaling` 状态，因此第二次热键会被解释为停止/切换请求。该请求不应成为崩溃的必要条件，但 fix1 必须覆盖“初始化中再次停止”的竞态。

## 3. 下拉菜单问题的结论

这不是同一个运行时根因，而是用户可见合同与现有 UI 行为不一致。

### 3.1 DLSS SR、DLSSFG、DLSSNR

当前参数标签为：

```text
Motion Vector Estimation
```

而用户寻找的是“光流质量”。虽然其五个值已经正确对应 `None/4F/4M/4S/2M`，标签和入口位置不足以让用户确认这是 NVOF 质量选择。

### 3.2 XeSSFG

现场配置为 `opticalFlowMethod=0`，即 `None`。现有 `_RefreshConditionalVisibility` 会在 `None` 时同时隐藏 AMD 和 NVIDIA 的质量控件：

```text
method == AMD     -> 仅显示 AMD 质量
method == NVIDIA  -> 仅显示 NVIDIA 质量
method == None    -> 两个质量控件都隐藏
```

逻辑本身符合 r4 原 TODO 的“隐藏或禁用”，但实际体验会被理解为“没有接入光流质量”。fix1 统一改为始终保留一个可见的“光流质量”位置；选择 `None` 时禁用并显示“不适用”，选择 AMD/NVIDIA 时切换相应选项集。

## 4. P0：修复 NVOF 共享输出纹理

- [ ] 将 NVOF 稠密 motion/confidence 输出的共享标志改为与现有 Frame Guidance NT-handle 路径一致的合法组合。
- [ ] 优先复用一个共享纹理创建 helper，避免 NVOF、Zero Provider、Adapter Cache 各自维护不同的 flag 合同。
- [ ] 创建后必须验证 `IDXGIResource1` 可取得，且 `CreateSharedHandle` 成功。
- [ ] 验证生成的 NT handle 可被目标 D3D12 设备通过 `OpenSharedHandle` 打开。
- [ ] 分别验证 `R16G16_FLOAT` motion、`R8_UNORM` confidence、`R32_FLOAT` depth。
- [ ] 覆盖奇数尺寸 `1924 × 1177`，不得只测试 16/32 对齐尺寸。
- [ ] 失败日志增加资源角色、格式、宽高、BindFlags、MiscFlags 和 HRESULT；不得只打印通用 `CreateTexture2D failed`。
- [ ] 若真正采用 `SHARED_KEYEDMUTEX | SHARED_NTHANDLE`，必须同时设计并验证 D3D11/D3D12 双端同步；不得只添加 flag 而不消费 mutex。

验收：RTX 5070 Ti 上四档 NVOF 均能完成 Frame Guidance 初始化，motion/depth 可被 DLSS SR、DLSSFG、DLSSNR 的 D3D12 消费路径打开。

## 5. P0：修复部分初始化失败后的闪退

- [ ] `NvidiaOpticalFlowProvider::DestroySession` 对任意初始化断点幂等：DLL、API 表、session、注册资源、SRV/UAV、query 可分别为空。
- [ ] `FrameGuidanceService` 初始化失败后清理已成功的 Zero/NVIDIA/AMD/Adapter 资源，不再把半初始化状态暴露给消费者。
- [ ] `Renderer::Initialize` 任一步失败后，析构顺序不得依赖完整 presenter、Frame Guidance、D3D11/D3D12 interop 或窗口已经创建。
- [ ] `ScalingWindow::Stop` 在 `_renderer` 仅构造但 `Initialize` 未完成时仍可安全重复调用。
- [ ] 清理期间撤销或忽略已经排队的 Toggle、StateChanged、toast、save 和 overlay 回调，防止回调访问已销毁对象。
- [ ] 为 dump 对应的空指针读取定位到具体函数和成员；Release 构建保留可归档的 PDB，或至少生成可匹配版本的 MAP。
- [ ] 初始化失败最终只能产生一个用户可见错误和一次 `Idle` 状态通知，不得抛出第二异常。

验收：故意令 motion/confidence 任一资源创建失败、NVOF API 创建失败、所选 grid 不支持或 D3D12 OpenSharedHandle 失败，Magpie 均显示准确错误并继续运行。

## 6. P0：封闭初始化期间的重复缩放请求

- [ ] 明确区分 `Idle`、`Starting`、`Scaling`、`Stopping`、`Waiting`，不再把完整初始化过程对 UI 暴露为稳定的 `Scaling`。
- [ ] `Starting` 期间再次收到相同热键时，只记录一次取消意图；不得并行启动第二次 Start 或重入 Stop。
- [ ] `Starting -> Failed` 与 `Starting -> Cancelled` 共用单次、幂等清理事务。
- [ ] 所有跨线程命令携带 run id/generation，过期的 Toggle、Stop、restart-with-parameters 命令不得作用于下一次缩放。
- [ ] 连续快速按缩放热键 2、5、20 次，最终状态必须确定且进程存活。

验收：在 NGX/NVOF 初始化最慢阶段按第二次热键，最多取消当前启动，不发生重入、悬挂、双重销毁或访问冲突。

## 完成定义

- 用户在所有指定消费者中都能明确找到并理解光流质量选择。
- NVOF 共享 motion/confidence 资源能够在 D3D11 生产端和 D3D12 消费端之间合法打开。
- DLSSNR 使用高质量 NVOF 时能够进入稳定缩放，不再返回错误码 `18`。
- 任一提供器、资源或 interop 初始化失败都只产生可操作错误，不导致 Magpie 退出。
- 初始化期间重复热键不会重入启动/停止或触发双重清理。
- Release x64、配置持久化、目标 GPU 实机矩阵和独立本地部署全部通过。
