## 目标与边界

- 修复效果链包含 DLSSFG 时，鼠标进入工具栏或参数窗口后按钮、滑块、滚轮可能失效的问题。
- DLSSFG 的生成帧顺序、共享纹理 FIFO、pacing 和槽位释放合同不得因 Overlay 重绘而被破坏。
- 缩放期间参数窗口的每个离散值必须严格遵守对应 MagpieFX `//!STEP`，显示精度也必须能表达该步进。
- 参数窗口允许用户从右下角拖动调整宽度和高度，并以 DPI 无关尺寸保存、恢复和限制到当前视口。
- 同时修复本次审查发现的同源问题：XeSSFG 静态画面交互、帧生成倍率类型、布尔识别不一致、长标签/小窗口布局以及 live apply 失败状态分叉。
- 不把 DLSSFG multiplier 或 Motion Vector 改为实时参数；两者仍需完整退出并重新缩放后生效。

## 已核实的现状与设计结论

### 1. DLSSFG 下无法点击不是单个按钮问题

- `Renderer::MessageHandler` 把鼠标按下/抬起直接写入 `ImGuiIO::MouseDown`，随后调用普通 `Render()` 让 ImGui 消费状态。
- 同步 DLSSFG 开启时，普通 `Render()` 会直接返回。这条保护是必要的：普通路径若取走“最新共享槽位”，可能越过仍在排队的生成帧，破坏生成帧在真实帧之前呈现的顺序。
- 因此不能用“删除 DLSSFG 下的 Render guard”修复交互。当前真正的问题是鼠标 down/up 没有排队，而 DLSSFG 下一次前台帧又可能晚于两条输入消息，导致 ImGui 看不到完整点击边沿。
- DLSSFG 前台 pacing 和连续 `WM_FRONTEND_RENDER_DLSSFG` 也运行在缩放窗口消息线程。高倍率或低刷新组合下，连续帧消息与等待可能推迟鼠标消息，进一步放大失效概率。
- 影响范围不限于工具栏：参数按钮、Pin、Profiler、Screenshot/右键菜单、退出按钮、参数复选框、滑块、滚轮、窗口移动和右下角缩放都依赖同一输入/重绘链路。
- XeSSFG 在没有新捕获帧时也主动抑制普通 Overlay-only present，以免把重复颜色帧喂给 SDK；静态源上存在同类交互延迟或丢失风险，必须一并验证，不能只特判 DLSSFG 名称。

### 2. 参数步进目前只是提交后吸附

- 主窗口参数 Flyout 直接把 `EffectParameterDesc::constant.step` 绑定到 XAML `Slider.StepFrequency`。
- Overlay 参数窗口使用原始 `ImGui::SliderFloat` / `SliderInt`；控件拖动本身是连续值，只有控件返回 changed 后才调用规范化函数吸附到 step。
- 这会出现拇指移动、显示值和实际提交值不完全一致的中间状态。浮点显示还固定为 `%.2f`，无法正确显示仓库中已有的 `0.001`、`0.005` 步进。
- Overlay 与 Renderer 各自复制了一份规范化算法，长期存在边界和舍入行为漂移风险。
- Overlay 当前仅凭整数范围 `0..1` 判定复选框，未像主窗口一样同时要求 `step == 1`，两处控件类型合同不一致。

### 3. 参数窗口当前被明确禁止调整尺寸

- 参数窗口宽度固定为 `420 DIP`，最大高度固定为 `700 DIP`，同时使用 `ImGuiWindowFlags_AlwaysAutoResize`；因此 ImGui 的右下角 resize grip 不会工作。
- 现有 `OverlayWindowOption` 只保存锚点与位置，不保存宽高。即使解除 `AlwaysAutoResize`，重新缩放、DPI 或显示器切换后也无法恢复用户尺寸。
- 当前窗口内容没有为窄宽度统一处理长标签与显式换行，底部“还原/保存/应用并重新缩放”也属于滚动内容；窗口缩小时可能出现文字越界或操作按钮不可达。

### 4. 同源状态问题

- DLSSFG 和 XeSS Multi-Frame Generation 的 multiplier 元数据声明为 `float`，但实际只接受 `2/3/4` 并在 Renderer 中舍入为整数。Overlay 因此会错误显示为浮点滑条。
- DLSSFG `useMotionVectors` 已是 `int 0..1 step 1`，应继续显示开关；它需要重启的直接原因应标为 `FrameGuidance`，而 multiplier 才标为 `FrameGeneration`。
- `_effectParametersLiveFailed` 当前只被置位，没有完整的可见状态、清除规则或失败值回滚。即时入队失败时也不会进入 backend result 队列，可能没有 toast，draft 与实际画面会长期分叉。
- backend 的成功/失败回执带 revision，但 Overlay 尚未按参数维护“最后成功值/最后确认 revision”；旧回执有机会在连续拖动时被误解释成当前值的结果。

## A. 帧生成模式下的 Overlay 输入与重绘

### A1. 输入事件队列

- [ ] 将鼠标按键与滚轮输入改为 ImGui 事件队列接口，例如 `AddMouseButtonEvent`、`AddMouseWheelEvent`；不得继续只覆盖 `io.MouseDown` / `MouseWheel` 当前状态。
- [ ] down 和 up 必须各自入队并保序，即使二者发生在同一呈现帧之间，也要让 ImGui 消费到完整点击边沿。
- [ ] 不得用陈旧的 `io.WantCaptureMouse` 丢弃必要的 button-up；一旦 Overlay 捕获了按键，释放事件必须送达并正确释放 `CursorManager::IsCursorCapturedOnOverlay`。
- [ ] 明确首次进入 Overlay、工具栏自动隐藏/显现、弹出菜单、拖动滑块后移出窗口再释放等情况下的捕获规则，避免粘住按钮或源窗口收不到后续输入。
- [ ] 输入队列设有界限并在 Overlay 全部关闭、缩放结束或 Renderer 重建时清空，不能跨会话重放旧点击。

### A2. 安全的 Overlay 重绘请求

- [ ] 增加统一的 `RequestOverlayRedraw`/pending 标记，鼠标按键、滚轮、窗口拖动和 live apply 回执都通过该入口请求下一次前台绘制。
- [ ] 普通呈现路径可继续复用最新 backend 帧；同步 DLSSFG 路径绝不能调用会消费共享 FIFO 槽位的普通 `Render()`。
- [ ] 每次 DLSSFG FIFO 正常呈现时，在 frontend 侧保留一份“不含 Overlay/软件光标”的最后已呈现基础画面缓存，供静态画面上的 Overlay-only redraw 使用。
- [ ] 若 DLSSFG FIFO 仍有待呈现帧，则只记录 pending，由下一条有序 FIFO 帧顺带处理 Overlay 输入；若 FIFO 已空且已有有效基础画面，才允许从私有缓存执行 Overlay-only present。
- [ ] Overlay-only present 不得读取、占用、释放或修改 DLSSFG ring slot，不得更新 `_latestSharedTextureSlot`，不得冒充生成帧或真实帧，也不得改变 generated-before-real 顺序。
- [ ] 第一帧尚未呈现时不执行缓存重绘；保留输入到首个有效前台帧，不显示未初始化纹理。
- [ ] 对 presenter `BeginFrame`/`EndFrame` 失败、设备丢失、窗口销毁和 session stop 做对称清理，不能泄漏 ring event、缓存纹理或鼠标捕获。

### A3. 消息与 pacing 公平性

- [ ] 统计“已发布但未处理”的 DLSSFG 前台帧数，使 Overlay redraw 能可靠判断 FIFO 是否空闲。
- [ ] 审查前台高精度等待和 DWM 等待，避免在窗口过程里长时间阻塞输入；不得通过窗口过程内无界重入式 pump 消息换取可点击性。
- [ ] 连续 DLSSFG 帧必须保持严格 FIFO，但鼠标输入、关闭窗口和设备错误消息不能被无限推迟；为输入到下一次 Overlay frame 的延迟建立上限和日志。
- [ ] 保留现有 ring wait、generated/real publish 与 frontend timing 诊断，并补充 overlay redraw、queued input、最大输入延迟和 deferred redraw 计数。

### A4. XeSSFG 同类路径

- [ ] 复查 XeSSFG 的静态源交互；Overlay-only redraw 不能作为新的源颜色帧进入 XeSSFG，也不能提高 SDK 观察到的输入帧率。
- [ ] 若 XeSSFG presenter 支持在 SDK 输出之后安全叠加，使用与 DLSSFG 等价的 frontend 私有缓存；否则至少保证输入事件排队并在下一帧可靠执行，且 UI 明确不会丢点击。
- [ ] DLSSFG 与 XeSSFG 的通用输入修复放在呈现能力层，不散落为按 effect 名称判断的按钮特例。

## B. DLSSFG / XeSSFG 参数合同

- [ ] 将 `DLSSFG\DLSS_FrameGeneration.multiplier` 从 `float` 改为 `int`，保持 `default=2`、`min=2`、`max=4`、`step=1`。
- [ ] 同步将 `XeSSFG\XeSS_MultiFrameGeneration_ZeroMV.multiplier` 改为 `int`，避免同一离散倍率在两个帧生成器中呈现不同控件。
- [ ] `DLSSFG.useMotionVectors` 继续声明为 `int 0..1 step 1` 并显示与 DLSSNR 相同的开关。
- [ ] runtime capability 按参数给出原因：DLSSFG multiplier 为 `RestartRequired/FrameGeneration`，`useMotionVectors` 为 `RestartRequired/FrameGuidance`。
- [ ] 保持两项只写 draft；拖动/切换、保存本身不得重建 NGX Feature、Frame Guidance、共享纹理或 pacing。
- [ ] “应用并重新缩放”后重新解析并验证 multiplier 与 Motion 开关；非法旧配置仍做 finite、round、clamp，不得导致初始化崩溃。
- [ ] 检查包含 DLSSFG 的复合效果链，而不只检查内置 `DLSSFG` 模式；DLSSFG 位于链首、中间、链尾时参数索引、显示名称和 restart 标记均正确。

## C. 严格遵守参数 STEP

### C1. 单一数值合同

- [ ] 抽出 Overlay 与 Renderer 共用的参数数值规范化工具，统一处理 finite、min/max、整数舍入和 step 格点；删除两份重复实现。
- [ ] 明确合法格点为 `min + n * step`，使用稳定的 double 中间计算和最终 clamp，避免 `0.05` 等二进制浮点误差产生脏值。
- [ ] 对 `step <= 0`、非有限 float、`min > max` 或格点数量溢出的第三方效果元数据安全拒绝或降级，并记录 effect/parameter；不得把非法范围直接传给 ImGui。
- [ ] 布尔控件仅在参数类型为 `int` 且 `min=0/max=1/step=1` 时启用；float `0..1` 或其他整数步进仍显示离散滑条。
- [ ] 初始化值、鼠标拖动值、还原值、保存值、live mailbox 值和 backend 最终值全部经过同一合同，显示值必须等于提交值。

### C2. ImGui 离散滑条

- [ ] 不再依赖连续 `SliderFloat` 返回后再吸附；滑条内部使用离散 tick/index，拖动过程中只能产生声明 step 对应的值。
- [ ] 整数滑条同样按 step 映射 tick，确保 `step=4/10/16` 时不会短暂产生中间整数。
- [ ] 根据 step 自动推导显示小数位：至少正确覆盖 `0.001`、`0.005`、`0.01`、`0.05`、`0.1`、`0.5` 和整数步进，不固定使用 `%.2f`。
- [ ] 显示文本去除浮点噪声，同时保留表达 step 所需的末尾位数；`0.005` 必须可区分相邻值。
- [ ] 持续拖动仍使用 last-write-wins mailbox；增加离散 tick 后不得为每个像素移动制造无界任务。

- [ ] `Deband` 的整数 `step=4`、`GTU` 的 `step=10/16` 以及 DLSSFG/XeSSFG 的 `step=1` 不出现非法中间值。
- [ ] 同一个效果在主窗口参数 Flyout 与缩放 Overlay 中选到同一位置时，得到完全相同的参数值。

## E. Live apply 状态一致性补强

- [ ] 把每个 Live 参数的 `draftValue`、`lastSubmittedRevision`、`lastAppliedRevision` 和 `lastAppliedValue` 分开维护。
- [ ] 只接受不旧于该参数当前确认状态的回执；旧成功/失败不能覆盖后续拖动的状态。
- [ ] 即时 mailbox 入队失败与 backend apply 失败使用同一可见错误路径；无论参数窗口当时开关状态，都不能只设置一个永远不展示的 bool。
- [ ] 失败后把相应 draft 回退到最后成功 runtime 值，或明确标为未应用并禁止把它伪装成当前画面值；选择的语义需在中英文提示中一致。
- [ ] 后续成功可清除对应失败，不能让一次旧错误永久显示；关闭再打开参数窗口也不得把失败值误标为“实时已应用”。
- [ ] `还原`、快速连续拖动、多个参数同一 backend 批量更新以及窗口关闭时，回执和保存状态保持一致。

## 建议实施顺序

1. `fix(core): queue overlay mouse input and preserve frame-generation FIFO`
2. `fix(core): validate discrete frame-generation parameter metadata`
3. `fix(overlay): honor effect parameter step and display precision`
4. `feat(overlay): resize and persist the effect parameter window`
5. `fix(overlay): reconcile live parameter acknowledgements and failures`
6. `test(release): validate frame-generation overlay interaction and deploy r3 fix1`

## 实施摘要（2026-09-04）

- 鼠标按钮和滚轮改用 ImGui 输入事件队列；Overlay 捕获过的按键释放不会再被陈旧的 `WantCaptureMouse` 丢弃，关闭 Overlay 时会对称释放输入状态。
- 同步 DLSSFG 增加前台私有基础帧缓存和 Overlay-only 重绘路径；该路径不读取、占用或释放共享 FIFO 槽位，并以待处理前台帧计数阻止越序呈现。XeSSFG 不提交重复颜色帧，排队输入留到下一次真实捕获帧处理。
- DLSSFG/XeSSFG multiplier 元数据统一为整数；DLSSFG Motion Vector 保持布尔开关，重启原因分别标记为 Frame Generation 与 Frame Guidance。
- Overlay 数值控件统一通过共享归一化工具按 `//!STEP` 映射为离散 tick，显示精度由 STEP 推导；布尔识别严格限定为 `int 0..1 step 1`。
- 参数窗口移除固定尺寸和 `AlwaysAutoResize`，支持右下角拖拽、动态视口约束、长标签换行、固定底部操作区，以及以 DIP 保存和恢复用户宽高。
- Live 参数按参数维护 draft/runtime/submitted/applied revision；入队或后端应用失败时回退到最后确认值并显示提示，后端回执本身也会触发静止画面的 Overlay 重绘。

## 完成定义

- DLSSFG 及同类帧生成路径中，Overlay 所有鼠标交互可靠，不通过消费最新 ring slot 或插入伪颜色帧换取响应。
- DLSSFG/XeSSFG 倍率为整数离散控件，Motion Vector 为开关，restart reason 与实际资源依赖一致。
- Overlay 中所有参数严格按 `//!STEP` 移动、显示、保存和提交，与主窗口数值一致。
- 参数窗口可从右下角调整宽高，并在 DPI、显示器、普通退出和参数重启后安全恢复。
- live apply 失败不会留下“UI 显示新值但画面仍是旧值”的静默分叉。
- Release 构建、目标 GPU 人工验证、打包扫描与部署证据齐全。
