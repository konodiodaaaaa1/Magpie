## 2. DLSS 三个效果增加“无”

### 2.1 直接原因及影响

源码位置：

- `src/Effects/DLSS/DLSS_SR.hlsl:9`：`motionVectorQuality` 只有 OPTION 1–4。
- `src/Effects/DLSSFG/DLSS_FrameGeneration.hlsl:16`：同上。
- `src/Effects/DLSSNR/DLSSNR_AI_Filter.hlsl:71`：同上。
- `src/Magpie.Core/include/EffectParameterValue.h`：`NormalizeEffectParameterValue` 只接受 Choices 内的值；当前 0 不在 Choices 中，会返回默认值 2。
- `src/Magpie/EffectParametersViewModel.cpp`：设置页通过上述函数规范化当前选择。

这不只是少显示一个选项：旧配置中的 0 在经过该选项规范化路径时也不能作为有效 Choice 保留。直接修复点是效果元数据，不是 ComboBox 绑定、集合类型或 UI 兼容逻辑。

后端已有支持：`FrameGuidanceTypes.h` 的 `NvidiaOpticalFlowQuality::None` 与 `MotionVectorRequest::Nvidia(None)`；DLSS SR、NR、FG 均接受质量值 0，并有不消费估计运动向量、提交零运动向量的路径。`ScalingModesService.cpp` 的 DLSS 配置规范化本来就允许 0–4。

### 2.2 目标合同

标签保持 `OF Quality`，无额外档位说明。

| 0 | 无 | None | 不请求估计光流，消费零运动向量 |
| 1 | 性能 | Performance | 4x4 Fast |
| 2 | 均衡 | Balanced | 4x4 Medium |
| 3 | 质量 | Quality | 4x4 Slow |
| 4 | 超高质量 | Ultra Quality | 2x2 Medium |

## 3. XeSSFG 的 x2 与 MFG 倍率规则

### 3.1 SDK 合同

随附 `dependencies/XeSS-SDK-3.0.1/doc/xess_fg_developer_guide_english.md:75` 规定非 Intel GPU 需要支持 Shader Model 6.4，且最多生成一帧。每个真实帧额外生成 `multiplier - 1` 帧，因此两个效果在倍率为 2 时都只请求一帧，不能因为 ID 中有 MultiFrame 就增加 Intel 硬限制。

官方在线参考：[Intel XeSS-FG Developer Guide — Requirements](https://github.com/intel/xess/blob/main/doc/xess_fg_developer_guide_english.md#requirements)。本轮与随附 3.0.1 文档交叉核对；实施以实际随包 SDK 接口为准。

SDK 的 `xefgSwapChainGetProperties().maxSupportedInterpolations` 可在 proxy swap chain 初始化前查询。不能删除该检查，也不能把“非 Intel 允许 x2”解释为“任意显卡和驱动必定支持 x2”。Intel VendorId 也不是充分条件，仍需 SDK 返回支持能力。

### 3.2 确认存在的四层限制

| 位置 | 当前行为 | 目标行为 |
|---|---|---|
| `XeSS_MultiFrameGeneration_ZeroMV.hlsl:8` | MIN=3，MAX=4，DEFAULT=3 | 允许 2–4；默认 3 保留，除非用户另有指定 |
| `Renderer.cpp:213` | MFG 参数读取范围 3–4，回退 3 | 合法范围 2–4；显式选择 2 必须保留 |
| `Renderer.cpp:254` | MultiFrame 且 VendorId 非 0x8086 即拒绝 | 仅当请求倍率 >2 且非 Intel 时拒绝 |
| `XeSSFGPresenter.cpp:415` | MFG 请求小于 3 时失败 | MFG 接受 2–4；独立 X2 仍只接受 2 |
| `ScalingModesService.cpp:387` | 将 MFG 的 2 视为非法并归一化为 3 | 允许并持久化 2，移除这条强制迁移 |

- [x] 保留 variant 对“独立 x2 / 多倍率效果”的区分；硬件限制按实际 multiplier 判断。
- [ ] 两种效果在 x2 下都请求 `maxInterpolatedFrames=1`、`numInterpolatedFrames=1`。
- [ ] x3/x4 保留适用的 Intel 要求，并由 SDK 最大插帧数最终确认；不使用显卡型号白名单。
- [ ] 保留请求倍率超过 SDK 能力时的明确失败，禁止静默降档。
- [x] MFG x2 失败文案不得再一概称为“当前 Intel 显卡无法初始化”；Presenter 的错误分类按 requestedMultiplier > 2 判断。
- [ ] 旧配置中的显式 2 不能再变成 3。已被 fix2 保存成 3 的配置无法辨别原来是 2 还是用户主动选了 3，不批量改回 2，也不猜测用户原值。
- [ ] 一条链仍最多含一个 FG 效果；“MFG 允许 x2”不表示允许同时添加独立 x2 和 MFG。

## 7. 实施期间新证据与验收记录

### 7.1 XeSSFG x2 确认存在的启动阻断根因

本机 NVIDIA 适配器 `VendorId=0x10DE, DeviceId=0x2C05` 上运行独立、无窗口的 GPU 诊断程序，复刻 Presenter 的设备、共享 fence、纹理和 XeLL / XeSS-FG context 初始化调用。

- D3D11 / D3D12、共享 fence、XeLL context、sleep mode、XeSS-FG context 与 latency connection 均成功。
- `xefgSwapChainGetProperties` 成功，`maxSupportedInterpolations=1`，即支持 x2。
- 原 `XeSSFGPresenter::CreateSharedColor` 仅设 `D3D11_RESOURCE_MISC_SHARED_NTHANDLE`，真实 `CreateTexture2D` 返回 `0x80070057 (E_INVALIDARG)`。
- 同参数补充 `D3D11_RESOURCE_MISC_SHARED` 后，纹理创建、NT handle 创建和 D3D12 `OpenSharedHandle` 均成功。
- AMDOF 的输入/稀疏流共享纹理以及稠密运动向量/置信度输出也有相同缺失标志，已在该提供器内一并修复。没有更改其他效果器或全局纹理 helper。

这证明源码中存在确定的资源初始化阻断，与 x2 厂商限制无关。并不将缺失的用户原始失败日志补写成已捕获，也不等于整条真实缩放/呈现流程已实测成功。
