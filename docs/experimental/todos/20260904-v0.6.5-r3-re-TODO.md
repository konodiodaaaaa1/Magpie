# v0.6.5 r3 re TODO：回退补丁式输入系统并精简重做缩放参数调节

基线：当前 `0.6.5` 分支上的 v0.6.5 r3 fix4 工作树，HEAD 仍为 `84d9f6abb8203a79f9a44d9a66984a293e68856d`。

参考实现：[SAOG0721/Magpie PR #4：Live effect parameter editing in the scaling overlay](https://github.com/SAOG0721/Magpie/pull/4)。参考其参数窗口、运行时参数副本和 backend-thread 应用结构，不直接采用其中“运行时重建 DLSSFG/native backend”的策略。

本文记录 r3 初版至 fix4 的复盘结论和重做清单。本轮只准备 TODO，不修改产品代码、不构建、不部署。

## 结论摘要

- 当前问题不是缺少一个 `WM_LBUTTONUP` 分支，而是 fix1～fix4 先后建立了多套鼠标所有权、输入推进和视觉重绘机制；这些机制彼此校正、彼此取消，已经超过参数窗口本身需要的复杂度。
- “按下后不能及时释放”从 fix1 开始出现。fix1 把直接状态写入改成 ImGui 输入事件队列，同时引入 DLSSFG 私有基础帧、Overlay-only present 和多 presenter 分支；输入是否被消费开始依赖额外的帧推进。
- fix2 加入 `SetCapture`、handled 返回链、捕获期间 mouse-move 重绘和四槽状态栏。它没有消除 fix1 的消费时序问题，却让延迟的按下状态继续持有 Win32 capture，并让 Overlay 消息提前截断缩放窗口原有处理。
- fix3 将输入与呈现拆为 input tick/redraw tick，但仍保留额外 CPU-only ImGui frame、多个 pending 标记、DLSSFG/XeSSFG 专用呈现策略及参数回执状态。
- fix4 又加入鼠标状态机、消息泵优先级、`GetAsyncKeyState` 校正、焦点/capture cancel 和输入队列剩余量驱动。当前工具栏完全不能单击是 fix4 的直接回归，而不是新的工具栏布局错误。
- r3 re 不继续修补 fix4。先完整拆除 fix1～fix4 的输入/重绘旁路，恢复可点击的 Overlay 基线，再按 PR #4 的结构只重做参数窗口和参数应用。

## 已核实的证据

### 1. PR #4 没有重写 Magpie 的输入系统

- PR #4 总计修改 18 个文件，核心是 `OverlayDrawer`、`Renderer`、效果后端接口、保存回调和资源字符串。
- PR #4 没有修改 `ImGuiImpl.cpp/.h`、`ScalingRuntime.cpp`、`ScalingWindow.cpp/.h` 或自定义窗口消息常量。
- PR 的参数窗口直接加入现有 `OverlayDrawer::Draw`；参数变更投递到 backend thread，更新后强制一次 render。它没有引入独立 input tick、redraw tick、物理键轮询或第二套窗口过程分发。
- PR 后续提交允许运行时重建 DLSSFG 并按最大槽位常驻分配。r3 re 不采用这部分：DLSSFG、Frame Guidance、资源尺寸和 inline shader 相关参数继续归为 `RestartRequired`，通过完整退出/重新缩放生效。

相关平台依据：

- [Microsoft `PeekMessage` 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-peekmessagea)明确说明无过滤时 queued message 的默认次序是 posted message 先于 hardware input，并建议用消息范围过滤让 input 优先；因此 DLSSFG posted frame 的公平性应在消息泵用一条窄规则解决，不应扩散到 ImGui 状态机。
- [Dear ImGui 输入事件 API 说明](https://github.com/ocornut/imgui/issues/4921)说明 down/up 同帧会由 trickle queue 按需跨 frame 展开；因此不能用物理键最终状态替代尚未被 UI frame 消费的真实边沿。
- [Dear ImGui 1.91.8 Win32 backend](https://github.com/ocornut/imgui/blob/v1.91.8/backends/imgui_impl_win32.cpp)只使用一个 `MouseButtonsDown` 位掩码配合 `SetCapture`/`ReleaseCapture` 和 `AddMouseButtonEvent`，没有当前项目的四态按键机、物理键 reconcile 或多层 cancel。
- [Microsoft `WM_CAPTURECHANGED` 文档](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-capturechanged)说明窗口主动 `ReleaseCapture` 也会收到该消息；当前把正常 release 与 capture-changed cancel 都当成独立清理入口，天然容易重复结束同一次交互。

### 2. 当前实现相对参考实现明显膨胀

当前工作树相对 HEAD，仅下列 r3 核心/接线文件就增加约 2,043 行：

| 区域 | 当前新增规模 | 主要额外机制 |
| --- | ---: | --- |
| `ImGuiImpl.cpp/.h` | 293 行 | 五键状态机、Win32 capture 生命周期、cancel、物理键校正、内部队列计数 |
| `OverlayDrawer.cpp/.h` | 868 行 | 四份参数值、两份 revision、请求回执、参数审计、多列布局、CPU-only input frame |
| `Renderer.cpp/.h` | 606 行 | input/redraw tick、私有前端基础帧、三种 presenter 分流、双向回执队列 |
| `ScalingRuntime/ScalingWindow/SharedConstants` | 90 行 | 自定义消息、优先消息泵、handled 截断、每轮物理键校正 |
| `ScalingOptions/ScalingService` | 186 行 | session token、请求/结果协议、回调闭环、窗口尺寸持久化接线 |

这不是单纯的代码量问题；当前一次鼠标点击同时跨过 Win32 队列、Overlay ownership、Win32 capture、CursorManager capture、ImGui 事件队列、CPU input tick、GPU redraw/present 和物理键校正，任一层提前结束或延迟结束都会破坏单击。

### 3. 当前工具栏完全无法点击的直接机制

- `ScalingWindow::Render()` 每 2/8 ms 调用 `Renderer::ReconcileOverlayInput()`。
- `ImGuiImpl::ReconcileMouseButtons()` 在内部状态为 `Pressed`、但 `GetAsyncKeyState` 高位已经为 0 时，立即调用 cancelled release。
- 用户快速单击时，实体键可以已经松开，而对应 `WM_LBUTTONUP` 仍在当前线程队列中等待分发。此时 reconcile 先执行，调用 `ImGui::ClearActiveID()`，把本来应由真实 up 完成的按钮点击改成取消。
- 稍后真实 `WM_LBUTTONUP` 到达时，内部状态已经为 `Idle`，`_ReleaseMouseButton` 返回 false；按钮既没有正常 release，也不会产生 click。
- 这解释了“工具栏所有按钮都彻底点不了”，也解释了为什么继续调整按钮命中区或绘制次数无效。

### 4. fix1/fix2 与此前粘键的关系

- ImGui 的事件 API 会保留同一 UI frame 之间的 down/up；默认 trickle 行为也可能把快速 down/up 分散到多个 ImGui frame。事件队列本身不是错误，但要求 frame 推进时机单一且可靠。
- fix1 同时改变输入表示和 DLSSFG/XeSSFG 重绘方式，使 button edge 的消费不再只依赖原有 Overlay Draw；在安全 present 暂时不可用时，ImGui ActiveID 和队列中的 up 可以延后。
- fix2 的 `SetCapture` 保证消息归属，但 capture 只能决定消息送往哪个 HWND，不能保证 ImGui 何时消费该消息。延迟消费期间，窗口移动、resize grip、滚动条和 Slider 都会表现为同一种持续拖动。
- fix2 又让 `ImGuiImpl -> OverlayDrawer -> Renderer -> ScalingWindow` 返回 handled；Overlay 一旦认为消息属于自己，缩放窗口原有的源窗口聚焦和默认处理会被截断。由于判定依赖上一轮 `WantCaptureMouse` 与自建 ownership，这扩大了状态分叉。
- `WM_KILLFOCUS`、`WM_ACTIVATEAPP`、`WM_CAPTURECHANGED`、`WM_CANCELMODE`、物理键轮询和正常 button-up 都可能清理同一 ActiveID；正常释放和取消不再有唯一入口。

## r3 re 的目标与边界

- 恢复工具栏全部按钮、参数窗口单击、滑条、滚动条、窗口移动和右下角 resize grip 的正常按下/释放。
- 参数窗口继续从当前活动效果链的 `EffectDesc::params` 自动生成，不为各效果器写专用 UI。
- `Live` 参数在下一次 backend render 前应用；`RestartRequired` 参数只改 draft，点击一次“应用并重新缩放”后完整 stop/start。
- 所有暴露参数都有可见去向；不得因 Live 能力、依赖开关、非法元数据或布局宽度而静默消失。
- 保留参数 `//!STEP` 离散化、还原、保存、底部稳定状态摘要和用户调整窗口大小。
- 不在缩放期间重建 native backend、NGX Feature、Frame Guidance provider、DLSSFG 呈现环或 inline shader。
- 不改变 r1/r2 已完成的深度估算移除、DLSSNR 参数语义、Residual 计算、多列主窗口参数 Flyout 或效果文件清理。

## A. 先拆除 fix1～fix4 的输入与呈现旁路

### A1. 恢复单一 Overlay 输入入口

- [ ] 以 r2 fix4/HEAD 中原有 `ImGuiImpl` 输入结构为恢复参考，逐段删除 r3 后加入的 `MouseButtonState`、`HasMouseCapture`、`ReconcileMouseButtons`、`PendingInputEventCount`、`_AcquireMouseCapture`、`_ReleaseMouseButton`、`_FinishMouseCapture` 和 `_CancelMouseCapture`。
- [ ] 删除 `ScalingWindow::Render -> ReconcileOverlayInput`；禁止再用 `GetAsyncKeyState` 在正常 frame 中推测并取消一次尚未分发完成的点击。
- [ ] 删除用 `WM_KILLFOCUS`/`WM_ACTIVATEAPP` 直接 `ClearActiveID` 的鼠标取消逻辑。焦点事件只按 ImGui 标准接口报告焦点，不得冒充 button-up。
- [ ] 删除 `Renderer::MessageHandler` 的 handled 返回链和 `ScalingWindow::_MessageHandler` 顶部早退；恢复输入同时送入既有 Overlay 与缩放窗口正常流程。
- [ ] `OverlayDrawer::MessageHandler` 恢复为薄转发，不负责驱动绘制、present、参数应用或窗口销毁。

### A2. 删除自定义 input/redraw 调度

- [ ] 删除 `WM_OVERLAY_INPUT_TICK`、`WM_OVERLAY_REDRAW` 及对应 `CommonSharedConstants`。
- [ ] 删除 `ProcessOverlayInputTick`、`PresentPendingOverlay`、`_RequestOverlayInputTick`、`_RequestOverlayRedraw`、`ClearOverlayInput` 及全部 pending/coalesced 诊断字段。
- [ ] 删除 `OverlayDrawer::ProcessInput` 的 CPU-only ImGui frame；不再出现“先 EndFrame 消费输入、再由另一个消息视觉提交”的双阶段 UI。
- [ ] 删除 `_overlayInputNeedsSettle`、固定补两帧、根据 `InputEventsQueue.Size` 自循环补帧、redraw timer 和同类历史补丁；最终只能由正常 `OverlayDrawer::Draw` 推进一次 UI frame。
- [ ] 删除 `_frontendBaseTexture`、`_FrontendRenderOverlayOnly`、`_hasFrontendBaseFrame`、`_overlayRedrawPending` 和仅为参数窗口建立的 DLSSFG 私有缓存呈现路径。
- [ ] 删除 XeSSFG 的参数窗口专用 CPU input/present 分支。XeSSFG 不暴露参数时不为它维护第二套交互系统；有新真实帧时沿用正常 Overlay 绘制。

### A3. 保留一条最小消息公平规则

- [ ] 不保留 fix4 当前“quit -> 自定义 input tick -> PM_QS_INPUT -> generic”的四层调度，也不直接回退到可被 DLSSFG posted frame 长期占满的无过滤清空循环。
- [ ] 将缩放线程消息泵收敛为两类：一次处理一个现有 OS input/control 消息，再处理一个普通 queued message；两者交替且每轮有上限。
- [ ] input 优先只使用 Win32 官方 `PM_QS_INPUT`/明确 mouse range，不识别任何 Overlay 私有消息，不重排同一类别内部的 down/up 顺序。
- [ ] `WM_FRONTEND_RENDER_DLSSFG` 仍逐条按 FIFO 分发，不能合并、跳过或在单次 present 内重入；公平性只发生在两帧之间。
- [ ] `WM_QUIT`、窗口销毁和设备错误继续可及时退出。消息泵不读取 ImGui 状态、参数状态或实体按键状态。

## B. 按 Dear ImGui Win32 backend 精简鼠标适配

### B1. 只保留一个按键位掩码

- [ ] 参考 Dear ImGui 1.91.8 `imgui_impl_win32.cpp`，使用一个 `MouseButtonsDown` 位掩码记录由 Overlay 开始的 L/R/M/X 按键；不建立 `Idle/Pressed/Released/Cancelled` 枚举状态机。
- [ ] button-down 到达时按原始顺序调用 `AddMouseButtonEvent(button, true)`；button-up 无条件按原始顺序调用 `AddMouseButtonEvent(button, false)`，不得由当时可能过期的 `WantCaptureMouse` 丢弃配对 up。
- [ ] `WantCaptureMouse` 只决定是否把新的 down 标为 Overlay-owned/是否需要系统 capture，不决定是否把 OS 输入事件交给 ImGui。
- [ ] 第一枚 Overlay-owned 按键按下且当前没有其他 capture 时调用 `SetCapture(scalingHwnd)`；最后一枚释放且 `GetCapture()==scalingHwnd` 时调用 `ReleaseCapture()`。
- [ ] 不维护第二个 `_ownsWin32MouseCapture`、capture HWND 快照或 capture 起始时间；系统真实 `GetCapture()` 是唯一来源。
- [ ] `WM_CAPTURECHANGED` 不得在正常 `ReleaseCapture` 回调中再次生成 up 或清理 ActiveID。若确需处理外部夺取，只清空位掩码并排入缺失的 up，一次完成且不调用 `SetCapture`。

### B2. CursorManager 仍只负责 Magpie 光标路由

- [ ] 首枚 Overlay-owned down 时设置 `CursorManager::IsCursorCapturedOnOverlay(true)`，最后一枚正常/外部丢失释放时设置 false。
- [ ] 不再让 CursorManager capture、Win32 capture 和 ImGui ActiveID 互相反向推导；三者只有 down/up 两个同步点。
- [ ] 不从 `GetAsyncKeyState`、`GetGUIThreadInfo`、焦点变化或 presenter 状态修改按键位掩码。
- [ ] Overlay 关闭或缩放结束时使用一次简单 `ClearStates`：清空位掩码、在需要时释放本窗口 capture、清空 ImGui mouse state；不执行额外隐藏 frame 循环。

### B3. 输入处理不得执行 GPU 工作

- [ ] WndProc 中的 mouse down/up/move/wheel 只记录事件和光标状态，禁止直接调用 `Render`、`BeginFrame/EndFrame`、DWM wait、GPU fence 或 backend 参数更新。
- [ ] 下一次现有前端帧统一调用 `OverlayDrawer::Draw` 消费输入。普通、DLSSFG、XeSSFG 的差异只留在既有 presenter 路径，不进入鼠标适配器。
- [ ] 若普通静态源需要唤醒，只设置一个 `overlayInputDirty` 布尔值并让现有周期性 `Renderer::Render` 的 `NeedRedraw` 返回 true；不 Post 新的窗口消息。
- [ ] `overlayInputDirty` 在一次正常 Overlay Draw 后清除；它不记录边沿、不排队、不负责补帧。

## C. 以 PR #4 为骨架重写参数窗口

### C1. 最小数据模型

- [ ] `OverlayDrawer` 只保留 `startupValues` 和 `draftValues` 两份 UI 数据；当前真正生效的值由 Renderer 的 `runtimeEffectOptions` 持有。
- [ ] 删除 `_savedEffectParameterValues`、`_runtimeEffectParameterValues`、逐参数 submitted/applied revision 数组、apply result deque 和双向回执消费循环。
- [ ] draft 初始化从 `ScalingOptions::effects` 与参数默认值生成；Renderer 自动追加的 Bicubic 明确排除。
- [ ] 值统一经过现有 `NormalizeEffectParameterValue`：finite、范围、整数和 step 只实现一次。
- [ ] 保存成功后 App 侧负责 toast；Overlay 不维护一套异步请求结果状态机。入队或保存立即失败时只显示一次错误 toast。

### C2. 参数完整可见

- [ ] 顺序遍历每个用户效果器和每个 `EffectDesc::params`；除已从效果元数据真正取消暴露的参数（如 NR Preset）外，不允许 `continue` 静默跳过。
- [ ] DLSSNR 输入分辨率调整关闭时，不再隐藏 input percent 与 residual 参数；改为继续显示并标记/禁用本次会话无法 Live 的项，确保用户看得到并可决定是否为下次缩放修改。
- [ ] 非法参数元数据以禁用控件显示参数名和原因，不从列表消失；只在 Debug 日志输出 declared/drawn/invalid 计数，不在运行时建立永久审计数组。
- [ ] 效果链中无参数的效果器可跳过其空段，但不能导致后续效果器提前结束。
- [ ] r3 re 第一版参数窗口固定为单列纵向列表；`//!GROUP` 仅作为分隔标题。删除响应式 ImGui table、多列阈值、列间分隔线和横向布局算法。

### C3. 控件与窗口布局

- [ ] `int 0..1 step 1` 使用 Checkbox；其他 int 使用离散 SliderInt；float 使用基于 step tick 的滑条，显示精度由 step 推导。
- [ ] Label 只负责显示并保留显式换行，不解析 `(0 ..., 1 ...)` 文本生成枚举。
- [ ] 参数窗口移除 `AlwaysAutoResize`，首次显示使用约 `420 x 600 DIP`，设置合理 min/max constraint，并直接使用 ImGui 原生右下角 resize grip。
- [ ] 删除 width/height/layoutVersion/saveSize 的跨会话持久化和 `imgui_internal` resize-corner 检测。用户可在当前缩放会话调整大小；重新启动使用安全默认尺寸。
- [ ] 参数列表使用一个纵向滚动 child，最后一个效果器的最后一个参数始终可达；不使用水平滚动。
- [ ] 底部顺序固定为“还原 / 保存 / 应用并重新缩放”按钮，然后是一行固定高度状态摘要。状态文本变化不得改变参数 child 高度。
- [ ] 删除四槽状态栏、永久 `Live applied` 行和每项重复长文本；每项只用紧凑 `[L]`/`[R]` 标记并通过 tooltip 解释。

## D. 精简 Live / RestartRequired 应用模型

### D1. 保留参数级能力，不保留回执状态机

- [ ] 保留 `EffectParameterApplyMode { Live, RestartRequired }` 和必要的 restart reason；同一效果器可同时包含两类参数。
- [ ] 能力表仍由 backend 初始化结果生成，但只包含 name、apply mode、reason；不携带 UI revision、request id 或状态槽数据。
- [ ] 普通非-inline MagpieFX、`FrameRate_Filter.targetFrameRate`、已明确支持的 DLSSNR 参数为 Live。
- [ ] inline shader、尺寸/资源相关参数、Motion provider 开关、DLSSFG multiplier/Motion 和未知 native backend 参数为 RestartRequired。
- [ ] 不采用 PR 的默认 native backend recreate；未显式声明 Live 的 native 参数绝不在当前会话重建。

### D2. 单一有界 live mailbox

- [ ] UI 对 Live 参数只提交 effect index、parameter index、规范化值；名称由后端使用当前 desc 校验，不在每次拖动复制字符串。
- [ ] 使用一个按 `(effectIdx, parameterIdx)` 覆盖的 last-write-wins map 和一个 wake flag；同一参数最多保留最新值，最多一个 backend wake task。
- [ ] 删除逐参数 revision、apply-result deque、前端轮询结果和成功回滚数组。backend apply 失败时记录 effect/parameter，并通过一次统一 toast 报错；下一次用户修改仍可重试。
- [ ] backend 在稳定帧边界按 effect 合并更新：普通 shader 只写常量缓冲，DLSSNR 调用明确的 live apply，Frame Rate Filter 重算限速。
- [ ] 任一 Live 更新成功后设置现有 `_forceNextRender`；不发送 Overlay redraw 私有消息，不创建前端基础帧副本。
- [ ] 保留 DLSSNR 参数 revision/dirty 位中与“同一捕获 frameId 重新 evaluate/composite”直接相关的内部逻辑；删除仅为 Overlay UI 回执服务的 revision。

### D3. RestartRequired 只走完整重新缩放

- [ ] RestartRequired 控件始终可编辑，但只修改 draft，不调用 Renderer live mailbox。
- [ ] “保存”只写回当前缩放模式，不改变当前 runtime。
- [ ] “应用并重新缩放”一次性保存完整 draft，当前 ImGui Draw 返回后再执行一次完整 stop/start；不得在按钮调用栈中销毁 Renderer。
- [ ] 重启保留当前源 HWND、全屏/窗口模式、裁剪、capture、cursor 和 profile 选项，仅替换 effect parameters。

## 完成定义

- 工具栏和参数窗口不再依赖自定义 input tick、redraw tick、物理键 reconcile 或多层 cancel 才能完成一次点击。
- 一次鼠标交互只有一条 Win32 -> ImGui -> Overlay Draw 路径；GPU/presenter 只决定何时显示，不决定按键是否已经释放。
- 所有公开参数可见且可达，Live/RestartRequired 语义清楚，实时更新和完整重新缩放各走唯一通路。
- 参数功能的核心结构接近 PR #4：Overlay 生成控件、Renderer 保存 runtime 副本并应用 live 参数、App 保存 draft；本地只保留参数级能力和完整重启这两项必要差异。
- 普通与 DLSSFG 路径均通过连续点击、长时间拖动、窗口 resize、静态源和异常退出矩阵后，才允许重新部署 r3 local。
