## 目标

- 在缩放工具栏中增加“效果参数”窗口，从当前缩放会话的 `EffectDesc::params` 自动生成控件。
- 真正能原地更新的参数在拖动或切换后实时生效，不中断缩放。
- 需要重新创建资源、SDK Feature、帧引导提供器或重新编译 shader 的参数允许编辑，但只先暂存。
- 多个待重载参数通过一次显式的“应用并重新缩放”完成完整退出和重新开始，不能在滑块拖动期间反复重建后端。
- 参数能够写回当前缩放模式；临时试调、保存、还原和待重启状态必须有清晰且可预测的语义。

## 参考 PR 的取舍

### 采用

- [x] 复用缩放 Overlay/ImGui，而不是在主窗口上叠加另一个 XAML 窗口。
- [x] UI 由 `EffectDesc::params` 自动生成，覆盖普通 MagpieFX、特殊控制效果和 native adapter，不为每个效果器编写一套界面。
- [x] 参数修改进入 backend thread，在下一次渲染前统一应用；源窗口静止时主动请求一次渲染。
- [x] Renderer 保存本次会话自己的效果参数副本，窗口 resize 后不得从启动时的 `ScalingOptions::effects` 把实时值覆盖回去。
- [x] 保留“还原”和“保存”能力，并通过回调把值安全写回应用侧的缩放模式。
- [x] `FrameRate_Filter` 抽出可重复调用的帧率限制更新逻辑，`StepTimer::Initialize` 再次调用前重置内部区间。

### 不直接采用

- [x] 不使用“整个效果器只有一个 `canEditLive` 布尔值”；同一效果器内可能同时存在实时参数和重启参数，必须按参数判定。
- [x] 不禁用需要重启的参数。它们应当可编辑、可保存，并显示“重新缩放后生效”。
- [x] 不让 `NativeEffectBackend::UpdateParameters` 默认在会话内重建 backend。未知 native 参数默认归为“需要重启”，避免 drain、Feature 创建失败或瞬时直通污染当前画面。
- [x] r3 不采用 PR 中“DLSSFG 始终按最大槽位分配、修改参数时重建 Feature”的方案。DLSSFG 参数统一走完整重新缩放，避免常驻额外共享纹理和运行中切换呈现环。
- [x] 不通过解析 Label 中的 `(0 ..., 1 ...)` 文本猜测控件类型。控件类型只由参数数值类型、范围和步进决定；Label 仅用于显示。
- [x] 不把“强制渲染一次”视为所有后端都已刷新；DLSSNR 当前会按 `frameId` 复用重复帧，必须同时处理参数 revision。

## 用户交互模型

### 参数状态

每个参数在当前缩放会话中解析为以下二者之一：

| 状态 | 行为 | UI |
| --- | --- | --- |
| `Live` | 修改合并后在下一次 backend render 前生效 | 显示“实时”标记 |
| `RestartRequired` | 只修改窗口中的 draft，不触碰当前 Renderer/backend | 显示“重新缩放后生效”标记和原因 |

能力以“当前运行会话”解析，不以 draft 推测。例如本次启动时 DLSSNR 未启用输入分辨率调整，则 residual 后处理没有已分配资源，相关参数在本次会话中应解析为 `RestartRequired`。

### 按钮语义

- [x] `还原`：恢复本次缩放启动时的全部参数。实时参数立即回写当前 Renderer；重启参数只恢复 draft。
- [x] `保存`：把当前 draft 写回缩放模式，但不打断缩放。已保存的重启参数继续提示“当前会话尚未生效”。
- [x] `应用并重新缩放`：仅在存在重启参数差异时显示或启用；隐式执行保存，然后对同一个源窗口、同一种全屏/窗口模式执行一次完整 stop/start。
- [x] 关闭参数窗口不丢弃本次会话 draft；重新打开时显示刚才的值。
- [x] 未保存 draft 在用户普通退出缩放后丢弃；参数窗口用 dirty 标记提示，不在拖动过程中频繁写磁盘。
- [x] 重启只由用户点击按钮触发；滑块变化、开关变化和保存操作本身不得自动重启。

### 窗口布局

- [x] 工具栏增加参数图标，打开独立的“效果参数”Overlay 窗口。
- [x] 按效果器分段，使用 `sortName` 作为显示名并保留效果链顺序。
- [x] 按现有 `//!GROUP` 顺序显示组标题；无组参数保持单组，不复制主窗口 Flyout 的硬编码规则。
- [x] `0/1` 整数显示开关，其他整数显示整数滑条，浮点数显示按声明步进吸附的滑条。
- [x] 标签中的显式换行原样显示；不能解析标签文本生成枚举或改变参数语义。
- [x] 顶部汇总“实时已应用”“有 N 项等待重新缩放”“有未保存更改”等状态。

## r3 初始参数能力表

| 效果/路径 | 参数 | 当前会话能力 | 原因或处理方式 |
| --- | --- | --- | --- |
| 普通 MagpieFX shader | 全部参数，且未启用 `InlineParams` | `Live` | 只重写常量缓冲区，再渲染现有效果链 |
| 普通 MagpieFX shader | 启用了 `InlineParams` 的全部参数 | `RestartRequired` | 参数已编译进 shader，需要重新编译效果链 |
| `FrameRate_Filter` | `targetFrameRate` | `Live` | 重算 `StepTimer` 上限及 DLSSFG 同步呈现间隔 |
| `DLSSNR_AI_Filter` | `style`、`intensity`、`localToneStrength`、`localStructureStrength`、`skinStructureStrength`、`useAutoMask`、`uiCorrection` | `Live` | 每帧提交给 NGX；必要时只重置一次 temporal history |
| `DLSSNR_AI_Filter` | `residualMultiplier`、`residualSaturation`、`residualLightness`、`shadowStructureMultiplier`、`reflectionGlowMultiplier` | 本次启动时已启用输入分辨率调整则 `Live`，否则 `RestartRequired` | 只更新 residual composite 常量；没有现成 residual 路径时不能伪装成实时生效 |
| `DLSSNR_AI_Filter` | `enableInputResolutionScaling`、`inputResolutionPercent` | `RestartRequired` | 改变内部处理尺寸及 reduced/residual 资源分配 |
| `DLSSNR_AI_Filter` | `useMotionVectors` | `RestartRequired` | 改变 Frame Guidance provider 需求和 temporal 输入拓扑 |
| `DLSS_SR` | `useMotionVectors` | `RestartRequired` | 改变 Frame Guidance provider 需求；不做仅能单向更新的隐式特例 |
| `DLSS_FrameGeneration` | `multiplier`、`useMotionVectors` | `RestartRequired` | 影响 NGX Feature、帧引导需求、共享纹理/呈现环和 pacing |
| `FrameGuidance_Motion` | `gain` | `Live` | 只更新诊断 shader 每帧写入的常量 |
| 其他已识别 native backend | 未明确声明为实时的参数 | `RestartRequired` | 安全默认值；由各 backend 显式开放实时能力 |
| XeSS Frame Generation | 当前无暴露参数；未来新增参数 | `RestartRequired` | 使用独立 presenter，必须完整重新缩放 |

## A. 参数级能力模型

- [x] 新增 `EffectParameterApplyMode { Live, RestartRequired }`，不要复用效果级布尔值。
- [x] 为 Overlay 提供与 `EffectDesc::params` 一一对应的只读运行时信息，至少包含参数名、解析后的 apply mode 和重启原因。
- [x] 普通 shader 根据实际编译出的 `EffectFlags::InlineParams` 判定，不根据全局设置的预期值猜测。
- [x] 为 `NativeEffectBackend` 增加参数级能力查询和显式的 live apply 接口；默认能力为 `RestartRequired`，默认不得重建 backend。
- [x] `FrameRate_Filter`、DLSSFG 等 Renderer 特殊路径也接入同一能力表，Overlay 不硬编码效果名。
- [x] 能力表在 backend 初始化完成后冻结为本次会话快照；resize 和 draft 修改不得悄悄改变标记。
- [ ] 为条件能力增加单元测试：DLSSNR residual 项在启动时 resolution scaling 开/关两种情况下分别解析为 Live/RestartRequired。

## B. 会话数据与线程边界

- [x] 保持三份数据语义分离：启动基线 `startupOptions`、backend thread 独占的 `runtimeOptions`、Overlay thread 独占的 `draftOptions`。
- [x] `ScalingWindow::Options().effects` 不得被 slider 直接修改；否则 restart-only draft 可能在 resize 时意外泄漏到当前 backend。
- [x] `_BuildEffects` 完成后，Renderer 保存 `runtimeOptions` 副本；`_ResizeEffects` 始终使用这份副本，保留已实时应用的值。
- [x] UI 传入 effect index、parameter index/name、规范化后的有限值和 revision；backend 再校验索引、名称、范围与 step。
- [x] 实现 last-write-wins mailbox：同一参数在一帧内的多次滑动只保留最后值，且最多排队一个唤醒任务，不能为每个鼠标采样无限追加 dispatcher lambda。
- [x] 在 backend thread 的稳定帧边界批量取出更新，先按 effect 合并，再一次性更新完整常量或 backend settings。
- [x] live apply 成功后请求一次新 render，确保静态源窗口也能看到变化。
- [x] live apply 失败时保留最后一次成功的 runtime 值，记录 effect/parameter/revision，并向 Overlay 返回失败状态；不能静默让 UI 与画面分叉。

## C. 普通 shader 与帧率限制

- [x] 为 `EffectDrawer` 增加只更新常量缓冲区的参数入口；复用现有实际 input/output texture 尺寸，不重建纹理、SRV/UAV、sampler 或 shader。
- [x] 对 `InlineParams` 效果拒绝 live apply，只保留 draft 和重启入口。
- [x] 证明 MagpieFX 尺寸表达式不读取暴露参数；如果未来允许参数参与 texture size，必须自动降级为 `RestartRequired`。
- [x] 从 `_InitBackend` 抽出 `_UpdateFrameRateLimits`，保存捕获方式计算出的原始帧率上限，并在 `targetFrameRate` 改变时重复计算。
- [x] `StepTimer::Initialize` 每次调用前恢复默认 interval，避免旧限制残留。
- [x] Frame Rate Filter 和 DLSSFG 同时存在时，同步更新呈现节奏；本轮不允许借此实时修改 DLSSFG multiplier。
- [x] 强制渲染不能破坏 duplicate-frame detection、benchmark mode 或前后台 pacing。

## D. DLSSNR 实时更新

- [x] 提取统一的 `ParseDLSSNRSettings`，初始化、能力判定、live apply 和 restart 都使用同一套默认值、finite 检查与 clamp。
- [x] live apply 只复制能力表允许的字段；任何 resize、guidance 或 Feature 创建相关字段进入该入口时应拒绝并记录错误。
- [x] `style`、NR 强度/结构、Automatic Mask 和 UI Correction 改变后，在下一次 NGX evaluate 设置一次 history reset，随后恢复正常累积。
- [x] 五个 residual 参数只更新 composite 常量，不重建 NGX Feature，也不重置 NGX temporal history。
- [x] 给 DLSSNR 增加 parameter revision。当前 `lastEvaluatedFrameId == frameId` 的重复帧快速返回必须同时检查 revision，否则静态画面上的参数变化不会刷新。
- [x] residual-only 更新优先复用最后一次有效的 reduced denoised 结果，只重新执行 composite；如果实现复杂，可先重新 evaluate，但必须记录额外成本并通过稳定性测试。
- [x] NGX evaluate 参数变化与 residual-only 变化使用不同 revision/dirty 位，避免每次微调后处理都无意义地重跑 Feature 18。
- [x] 若本次会话未创建 motion provider，`useMotionVectors=0 -> 1` 不能标成 Live；r3 统一要求重新缩放，避免方向相关的能力语义。
- [x] DLSSNR disabled fallback 路径也要响应 residual live 参数，并保持零 residual 时画面不变。

## E. Overlay 参数窗口

- [x] 在工具栏加入参数按钮并更新图标字体缓存版本；按钮状态、自动隐藏和窗口持久化沿用现有 Overlay 机制。
- [x] 初始化窗口时从启动参数和 `EffectDesc` 默认值构造 baseline/runtime/draft，不把 Renderer 追加的 Bicubic 当作用户效果器。
- [x] 值在进入 draft 前统一执行 finite、min/max、整数舍入和 step 吸附；显示值与实际提交值必须相同。
- [x] 所有 restart-only 参数保持可操作，并逐项显示重启标记；不能像参考 PR 第一版一样整体置灰。
- [x] DLSSNR 的依赖显隐沿用主窗口合同：draft 关闭 `enableInputResolutionScaling` 时隐藏输入比例与 residual 参数；再次打开时恢复原 draft 值。
- [x] 实时拖动时只发 Live 参数；RestartRequired 参数只改变 draft 和 restart dirty 状态。
- [x] 还原操作按 effect 批量提交，不能为每个参数制造无界队列。
- [x] 保存成功、保存目标冲突、live apply 失败、重启中和重启失败均提供中英文提示。
- [x] 参数窗口不因某个 effect 无参数而错位；当前效果链完全无参数时显示明确空状态。

## F. 保存与完整重新缩放

- [x] `ScalingOptions` 增加会话标识和参数保存/重启请求回调；回调只负责跨到 App UI thread，不能从 backend thread 直接访问 `ScalingModesService`。
- [x] 不只依赖 `scalingModeIdx`。保存前同时核对会话 token、模式索引、模式名、effect 数量和 effect 名称顺序，避免缩放期间重排/删除模式后写错目标。
- [x] `保存` 一次性写入完整 draft，并调用一次防抖的 `AppSettings::SaveAsync`；未知自定义参数不得被顺带删除。
- [x] `应用并重新缩放` 必须先通过同一份身份和结构校验，再更新内存配置并启动 restart transaction。
- [x] restart transaction 保留源窗口 HWND、全屏/窗口模式、profile/cropping/cursor/capture 等本次会话设置，仅替换 effect parameters。
- [x] 不在 ImGui `Begin/End` 调用栈中销毁窗口；按钮只提交请求，在当前 Overlay frame 完成后执行 stop/start。
- [x] 完整 stop 必须释放 Renderer、native backend、NGX Feature、Frame Guidance、共享纹理和 presenter，再用新参数正常走 `_InitBackend`。
- [x] 相同 transaction 内只允许一次重启；按钮进入 pending 状态，防止双击或连续消息形成重启循环。
- [x] 重启前先检查源窗口仍有效；若保存或校验失败，不停止当前缩放。
- [x] 重启初始化失败时走现有错误提示并停留在未缩放状态，不自动无限回滚/重试；保留启动基线以便用户手动还原。
- [x] 内部参数重启不能误触发自动缩放抑制、Smooth Motion 的应用重启逻辑或重复的 `IsScalingChanged` 通知。
