# v0.6.5 r3 re fix1 TODO：浮窗与光标统一刷新调度

基线：`0.6.5` 分支上的 v0.6.5 r3 re 工作树，HEAD 为 `84d9f6abb8203a79f9a44d9a66984a293e68856d`。

## 目标

- 浮窗状态继续由真实输入和自身状态变化驱动，不依赖光标是否移动。
- 浮窗与软件光标继续在同一次前端合成和 Present 中显示。
- 高频鼠标移动只生成最新位置对应的 UI 帧；按下、释放和滚轮不得被合并。
- 交互期间目标刷新间隔约 8 ms，空闲状态维持约 16 ms 的按需刷新。

## 执行清单

- [x] `WM_MOUSEMOVE`/`WM_NCMOUSEMOVE` 只记录待处理移动，由下一次正常前端 tick 采样 `CursorManager` 的最新位置。
- [x] 按键和滚轮到达前先刷新光标状态并推进一次待处理移动，保证同一消息批次内的命中判断使用最新位置。
- [x] button down/up、wheel 和 leave 保持即时 ImGui CPU frame，不与 pointer motion 合并。
- [x] CPU 侧 UI frame 在交互时限制为约 8 ms、空闲时约 16 ms；后端新帧和输入边沿仍可强制立即推进。
- [x] GPU 侧仍只由统一 `Renderer::Render` 路径决定是否合成；没有在 WndProc 中加入 Present、等待或 GPU 工作。
- [x] 光标变化和浮窗变化继续使用同一个 `_FrontendRender`，一次绘制浮窗与光标。
- [ ] 在普通呈现、DLSSFG 和 XeSSFG 下人工验证滑条、窗口移动、resize grip、滚轮及快速单击。

## 验收重点

- 移动光标时浮窗交互反馈与软件光标在同一可见帧出现。
- 快速“移动后立即按下”仍能命中工具栏或参数控件。
- 高频移动不会为每条 `WM_MOUSEMOVE` 同步生成完整 ImGui frame。
- 光标静止时的释放、滚轮、状态提示和工具栏透明度仍能独立更新。
- DLSSFG 继续只从既有 FIFO 呈现，XeSSFG 继续等待真实后端颜色帧，不增加伪输入帧。
