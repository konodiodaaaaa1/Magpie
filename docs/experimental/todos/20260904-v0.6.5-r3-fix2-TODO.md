# v0.6.5 r3 fix2 TODO：参数窗口鼠标捕获与稳定状态栏

基线：当前 `0.6.5` 分支上的 `v0.6.5-r3-local` 工作树，HEAD 为 `84d9f6abb8203a79f9a44d9a66984a293e68856d`。

本文合并记录 r3 fix2 的问题分析、实施清单与验收标准。创建本文时仅整理 TODO，不修改产品代码、不构建、不部署。

## 问题与目标

1. 在缩放 Overlay 的参数设置窗口中按下一次鼠标左键后，左键可能一直保持按下状态；实际松开鼠标不会结束滑条、窗口缩放等 ImGui ActiveID，也不会继续正常更新参数。
2. 参数滑条拖动依赖前端重绘。当前鼠标移动本身没有形成完整的 Overlay 重绘请求，静态画面及部分帧生成路径下可能只在按下或下一次视频帧到来时更新，无法保证实时调节。
3. 参数窗口的 Live applied、待重新缩放、未保存、请求处理中等状态提示位于参数列表上方。提示出现、消失或换行时会改变下面参数区域的纵向位置，造成参数选项上下跳动。
4. 状态提示应移动到窗口最底部，并使用不随状态内容变化的稳定布局；状态刷新不得改变参数区的位置、高度和滚动位置。

## 已确认根因

### 1. Overlay 只有逻辑捕获，没有 Win32 鼠标捕获

- `ImGuiImpl::MessageHandler` 在接收 `WM_LBUTTONDOWN` / `WM_RBUTTONDOWN` 后，只维护 `_mouseButtonsDown`，并调用 `CursorManager::IsCursorCapturedOnOverlay(true)`。
- `CursorManager::IsCursorCapturedOnOverlay` 当前只负责 Overlay 交互状态、光标状态和 `ClipCursor`，不等价于 Win32 `SetCapture`。
- 没有 `SetCapture` 时，鼠标松开消息不保证返回最初接收按下消息的缩放窗口；拖出控件、窗口命中区域变化、焦点切换或源窗口重新获得焦点时，`WM_LBUTTONUP` 可能被发送到其他窗口。
- 一旦 Overlay 没有收到配对的 button-up，`_mouseButtonsDown[0]`、ImGui `io.MouseDown[0]`、Slider/Resize ActiveID 和 `CursorManager` 的 Overlay 捕获状态都可能残留。

### 2. Overlay 的 handled 结果没有传回缩放窗口

- `ImGuiImpl::MessageHandler` 和 `OverlayDrawer::MessageHandler` 已能返回事件是否由 Overlay 接收。
- `Renderer::MessageHandler` 当前返回 `void`，`ScalingWindow::_MessageHandler` 调用后仍继续执行原有鼠标按下分支。
- 因此即使 Overlay 已经接收按下事件，缩放窗口仍可能执行 `_srcTracker.SetFocus()` 和默认窗口处理，扩大按下/松开被不同窗口接收的风险。

### 3. 捕获中断没有统一清理

- 当前只在正常收到 `WM_LBUTTONUP` / `WM_RBUTTONUP` 时清除对应状态。
- 尚未把 `WM_CAPTURECHANGED`、`WM_CANCELMODE`、Overlay 全部关闭和会话销毁纳入同一释放路径。
- 直接依赖 `io.WantCaptureMouse` 不足以处理释放事件；该值来自上一轮 ImGui frame，并且在窗口状态变化时可能已经过期。

### 4. 捕获期间的鼠标移动没有驱动稳定重绘

- ImGui 的鼠标位置由 `NewFrame` 查询，但 `WM_MOUSEMOVE` 当前不会被 Overlay 输入处理器标记为需要重绘。
- 普通动态视频可能被连续捕获帧掩盖；静态源、低帧率源、DLSSFG FIFO 忙碌或 XeSSFG 抑制重复 present 时更容易表现为滑条不跟手。
- Live 参数已经在 ImGui 控件返回 `changed` 时入队，不需要等到 button-up 才提交；应修复输入消费和重绘时机，而不是把参数更新改成“松开后统一提交”。

### 5. 状态提示参与了参数区的普通流式布局

- 参数窗口当前先绘制状态提示，再创建参数内容 child。
- 状态行数量及文本换行改变时，参数 child 的起点随之上下移动。
- 当前 footer 预留高度是固定公式，但没有把底部状态区域作为独立且稳定的布局组成部分。

## A. Win32 鼠标捕获生命周期

### A1. 正常按下与释放

- [ ] Overlay 接收第一个鼠标按键按下时，对缩放窗口 HWND 调用 `SetCapture`；Win32 捕获状态与 `_mouseButtonsDown` 的所有权由同一组件维护。
- [ ] 仅当按下位置属于 Overlay 且该按下事件已被接收时获取捕获；不得拦截源窗口、黑边、缩放窗口原生标题栏或调整大小区域的正常输入。
- [ ] 左右键分别维护状态；按住一个按键再按另一个按键时不得重复取得或提前释放捕获。
- [ ] 最后一个由 Overlay 接收的按键释放后，先向 ImGui 排入对应 button-up，再在确认当前捕获窗口属于缩放窗口时调用 `ReleaseCapture`。
- [ ] button-up 的接收不得依赖当时的 `io.WantCaptureMouse`；只要存在由 Overlay 接收的配对 button-down，就必须消费并完成释放。
- [ ] 保留 `AddMouseButtonEvent` 事件队列接口，不退回直接覆盖 `io.MouseDown[]`，避免同一呈现帧之间发生的 down/up 边沿丢失。

### A2. 异常取消与对称清理

- [ ] 处理 `WM_CAPTURECHANGED`：若捕获被其他窗口夺走，为所有仍记录为按下的按键向 ImGui 补充 button-up，并清空 `_mouseButtonsDown`。
- [ ] 处理 `WM_CANCELMODE`：使用与 `WM_CAPTURECHANGED` 相同的统一取消函数，不保留 Slider、按钮、窗口拖动或 resize grip 的 ActiveID。
- [ ] `ImGuiImpl::ClearStates`、Overlay 全部关闭、缩放停止和 Renderer 销毁都必须调用同一释放函数；若当前 Win32 capture 属于缩放窗口则释放，否则只清理本地状态。
- [ ] 正常 `ReleaseCapture` 引发的 `WM_CAPTURECHANGED` 必须幂等，不能重复排入释放事件或重复修改 CursorManager 状态。
- [ ] 缩放窗口 HWND 已销毁、设备丢失或 presenter 失败时也不得留下系统级鼠标捕获或 `ClipCursor`。

### A3. Overlay 与 CursorManager 合同

- [ ] 区分并记录两类状态：Win32 窗口捕获负责保证消息归属；`CursorManager::IsCursorCapturedOnOverlay` 负责 Magpie 光标映射、限制和穿透策略。
- [ ] 两类状态在首次按下、最后释放和异常取消时保持对称，但不得用逻辑捕获代替 `SetCapture`。
- [ ] 捕获期间允许鼠标在参数窗口、滚动 child、滑条、按钮和右下角 resize grip 之间移动；松开后立即恢复原有源窗口输入映射。

## B. 输入 handled 传播与实时重绘

### B1. handled 结果传递

- [ ] 将输入是否由 Overlay 处理的结果完整传递：`ImGuiImpl -> OverlayDrawer -> Renderer -> ScalingWindow`。
- [ ] `Renderer::MessageHandler` 改为返回 handled 状态，同时保留现有 Overlay redraw 调度。
- [ ] `ScalingWindow::_MessageHandler` 对已由 Overlay 接收的客户区鼠标消息直接返回 `0`，不得继续执行源窗口聚焦和默认按键处理分支。
- [ ] Overlay 未接收的鼠标消息保持原行为，不能破坏源窗口点击、窗口拖动、原生边框调整大小、黑边命中和右键行为。
- [ ] 即使 Overlay 在按下之后被关闭，配对的 button-up、capture changed 和 cancel 仍必须绕过 `AnyVisibleWindow` 的早退条件进入清理路径。

### B2. 拖动期间的重绘

- [ ] 当 Overlay 持有任意鼠标按键时，将 `WM_MOUSEMOVE` 识别为 Overlay 交互事件，并请求一次前端重绘。
- [ ] 高频 `WM_MOUSEMOVE` 使用 pending/coalescing 机制，最多保留一次未处理重绘请求；不得为每个鼠标采样无限堆积消息、任务或 backend 更新。
- [ ] 每次被消费的移动事件都在 ImGui `NewFrame` 前取得最新鼠标位置，使 SliderInt tick、窗口移动和 resize grip 跟随当前指针。
- [ ] Live 参数仍在控件产生合法离散 `changed` 时进入 last-write-wins mailbox；RestartRequired 参数只更新 draft，不因拖动重建效果器。
- [ ] 松开事件至少再请求一次重绘，确保 ImGui ActiveID、hover/active 样式、CursorManager 和窗口尺寸持久化全部收尾。

### B3. 普通、DLSSFG 与 XeSSFG 路径

- [ ] 普通呈现路径允许复用当前安全前端帧处理 Overlay 输入，不要求源窗口必须产生新画面。
- [ ] 同步 DLSSFG 继续使用 frontend 私有基础帧执行 Overlay-only redraw；不得读取、占用或释放 DLSSFG FIFO ring slot，也不得改变 generated-before-real 顺序。
- [ ] DLSSFG FIFO 非空时只记录一次 pending Overlay redraw；FIFO 空闲后必须消费最新鼠标状态和全部必要按键边沿。
- [ ] XeSSFG 不得为了鼠标移动把重复颜色帧伪装成新的 SDK 输入帧；输入必须可靠排队，并在下一次安全的真实前端帧中按顺序消费。
- [ ] 若 XeSSFG 无法在静态源上安全执行 Overlay-only present，应提供不提交 proxy swapchain 的 UI/input tick 或等价机制，使 Slider `changed` 和 Live 参数入队不依赖新捕获帧；画面显示可等待下一次安全 present，但鼠标释放状态不得等待。
- [ ] 三种呈现路径都必须保证 button-up/cancel 的 CPU 状态立即清理，不能因为“不允许立即 present”而继续保持按下。

## C. 参数窗口底部状态区

### C1. 三段式稳定布局

- [ ] 参数窗口改为三个独立区域：可滚动参数内容区、固定操作按钮区、最底部状态提示区。
- [ ] 移除参数列表上方的 Live applied、待重新缩放、未保存和请求处理中提示；状态信息统一由最底部状态区显示。
- [ ] 操作按钮位于参数区之后、状态区之前；状态提示是窗口内容的最后一段，符合“状态提示放在最下面”的交互要求。
- [ ] 参数内容区只使用扣除按钮区和状态区后的剩余高度，窗口整体 resize 时仍可滚动且按钮和状态始终可达。

### C2. 状态更新不得引发布局跳动

- [ ] 状态区使用稳定保留高度；高度不得根据当前状态是否存在、状态数量或一次运行时回调的出现/消失临时改变。
- [ ] 根据当前窗口宽度、DPI 和本地化文本预先计算状态区所需的固定上限，或使用固定行数状态槽；只允许用户 resize、DPI/语言或 viewport 变化时重新计算。
- [ ] 状态出现、消失、颜色变化和文本替换时，参数内容区的顶部、底部、可用高度及 `ScrollY` 保持不变。
- [ ] 没有状态时仍保留同样高度，可显示空白或中性就绪状态；不得让参数区占用该空间后又在提示出现时收缩。
- [ ] 超长本地化文本必须在状态槽内部换行、裁剪并提供 tooltip，或使用简短摘要加 tooltip；不得通过扩大 footer 推动参数区。
- [ ] 多个状态同时成立时使用确定的优先级或固定槽位组合，至少完整表达：Live 已应用、存在 RestartRequired 修改、存在未保存修改、保存/重启请求处理中、Live apply 失败。
- [ ] 状态区与操作按钮、窗口底边和 resize grip 保持足够间距；状态文本不得覆盖右下角调整大小热区。

### C3. 状态语义与刷新

- [ ] 状态展示由当前 draft/runtime/request/revision 状态派生，不新增与真实状态分离、需要手动复位的永久 bool。
- [ ] backend apply 成功/失败回调只更新对应状态内容并请求重绘，不改变窗口尺寸或重置参数滚动位置。
- [ ] Live apply 失败后的 draft 回滚、随后成功、保存成功、进入/退出 restart pending 时，状态优先级和颜色变化一致且无闪烁。
- [ ] 关闭并重新打开参数窗口时保留现有 draft 语义；底部状态区应立即反映当前状态，不先短暂显示错误的默认状态。

## D. 防御性检查

- [ ] 检查 ImGui 窗口移动、参数窗口 resize grip、滚动条拖动、Checkbox、SliderInt 和底部按钮是否全部共用同一捕获生命周期。
- [ ] 检查右键、双键组合、窗口外释放、Alt+Tab、Win 键/开始菜单、源窗口销毁和缩放退出，不得出现残留捕获。
- [ ] 检查 `AnyVisibleWindow`、自动隐藏 Toolbar 和参数窗口关闭路径，确保正常释放事件不会被可见性早退吞掉。
- [ ] 检查 `SetCapture`/`ReleaseCapture` 与缩放窗口原生移动、边框 resize 的系统捕获不冲突；只在 Overlay 实际接收客户区按下时取得捕获。
- [ ] 不改变参数范围、step、Live/RestartRequired 能力表、DLSSFG/XeSSFG 参数含义、效果器计算或 r2 多列分组。

## E. 验收矩阵

### E1. 鼠标状态

- [ ] 在滑条上单击后释放，`_mouseButtonsDown[0]`、ImGui `MouseDown[0]`、ActiveID 和 `CursorManager::IsCursorCapturedOnOverlay` 均恢复为空闲状态。

- [ ] 连续快速单击、快速拖动 10 秒、左右键交错以及拖动过程中关闭参数窗口，均不残留 capture 或无界输入队列。
- [ ] 拖动右下角 resize grip 后释放，窗口尺寸停止变化并正确保存；下一次左键点击仍能正常操作参数。

- [ ] 普通 shader Live 参数在动态和完全静态源上都随离散 tick 实时更新，松开后保持最后合法值。
