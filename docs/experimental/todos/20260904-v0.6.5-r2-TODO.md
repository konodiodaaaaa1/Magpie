## 目标与边界

- 点击效果器参数按钮后，一次展开并显示所有参数列；不再要求用户横向滑动才能看到其余列。
- DLSSNR 从三列收敛为 `Detail Control`、`DLSSNR` 两列，严格固定列名与参数顺序。
- 保留现有 `Residual Multiplier` 总强度，并新增 HSL 饱和度、HSL 明度、阴影/结构、反射/发光四个残差精调参数。
- 四个新参数范围均为 `0.00–2.00`、步进 `0.05`、默认 `1.00`。
- 默认值必须与 r1 当前画面等价；不能因新增 RGB/HSL 转换产生默认色偏、亮度漂移或额外裁切。
- 新控制只属于“启用输入分辨率调整后的残差重建”，不改变 DLSSNR Feature 18 本体的 NGX 参数语义。

## 已确认的现状

- 参数 Flyout 当前每列固定 `260px`、列间距 `16px`，外层 `ScrollViewer` 的 `MaxWidth=820` 且允许水平滚动。
- DLSSNR 当前分为 `Input`、`NR`、`Detail` 三列；`Use Motion Vectors` 仍在 `NR` 列。
- `Residual Multiplier` 仅在 `Adjust Input Resolution` 开启时显示；即使输入比例为 `100%`，开启该功能仍会执行残差合成。
- 当前残差为 `ReducedDenoised - ReducedColor`，经过 Lanczos3 横向/纵向上采样后直接执行：

  ```text
  output = saturate(original + residual * ResidualMultiplier)
  ```

- 当前合成同时覆盖正常 DLSSNR 输出和 native backend 失效后的回退输出；r2 的新逻辑必须覆盖两条路径。

## C. 残差精细控制合同

### C1. “0–127 / 128–255”的内部定义

- [x] 不把原画面像素亮度 `0–255` 当作残差区间。当前残差在 shader 中是有符号浮点差值，零差值对应居中的诊断表示：

  ```text
  residual8 = round(saturate(residual * 0.5 + 0.5) * 255)
  ```

- [x] `residual < 0` 对应约 `0–127`，定义为让画面变暗的阴影/结构部分；乘以 `Shadow / Structure Control`。
- [x] `residual > 0` 对应约 `128–255`，定义为让画面变亮的反射/发光部分；乘以 `Reflection / Glow Control`。
- [x] 精确的 `residual == 0` 是中性点，不受任一倍率影响。实际 shader 直接按浮点正负拆分，不先量化成 8-bit，避免阈值台阶和色带。
- [x] 正负拆分按 RGB 分量执行，建议公式为：

  ```text
  controlledResidual =
      min(residual, 0) * shadowStructureMultiplier +
      max(residual, 0) * reflectionGlowMultiplier
  ```

- [x] 为混合正负 RGB 分量、纯亮度差、纯色度差和零差值分别准备测试向量，确认两个倍率只影响各自符号部分。

### C2. HSL 饱和度与明度控制

- [x] HSL 控制针对“DLSSNR 相对原图产生的变化”，不是对整张原图无条件调色；参数为 `1` 时保留当前变化，`0` 时移除对应变化，`2` 时将对应变化放大到两倍并裁切到合法范围。
- [x] 在完整分辨率纵向合成阶段，以旧算法候选结果和原图为输入：

  ```text
  rawResidual = upsampledResidual * residualMultiplier
  candidateRGB = saturate(originalRGB + rawResidual)
  originalHSL = RGBToHSL(originalRGB)
  candidateHSL = RGBToHSL(candidateRGB)

  candidateHSL.s = saturate(
      originalHSL.s +
      (candidateHSL.s - originalHSL.s) * residualSaturation)
  candidateHSL.l = saturate(
      originalHSL.l +
      (candidateHSL.l - originalHSL.l) * residualLightness)

  hslControlledRGB = HSLToRGB(candidateHSL)
  hslControlledResidual = hslControlledRGB - originalRGB
  signedControlledResidual =
      min(hslControlledResidual, 0) * shadowStructureMultiplier +
      max(hslControlledResidual, 0) * reflectionGlowMultiplier
  outputRGB = saturate(originalRGB + signedControlledResidual)
  ```

- [x] Hue 使用 `candidateHSL.h`，本轮不新增 Hue 参数；灰色、近零饱和度及 Hue 环绕必须有稳定的无 NaN 实现。
- [x] HSL 运算使用当前 residual composite shader 收到的归一化 RGB 工作空间；先核实 SRV 格式是否为 sRGB 视图，并在代码注释中写明是否发生传递函数转换，避免同一参数在不同输入格式下语义漂移。
- [x] Alpha 始终保留 `storedOriginal.a`，四个新参数不得改变透明度。
- [x] 当四个新参数均为 `1.0` 时直接走原有 `original + residual * ResidualMultiplier` 等价路径，避免默认设置发生 RGB↔HSL 往返误差并减少默认 GPU 开销。
- [x] 只在任一新参数偏离 `1.0` 时执行 HSL 与正负分段控制；比较方式使用传入后已按步进/范围规范化的值，不依赖 UI 字符串。

### C3. 运算顺序与预期

- [x] 固定顺序为：旧 `Residual Multiplier` 总增益 → HSL 饱和度/明度差值控制 → 阴影/结构与反射/发光正负分段 → 最终裁切。
- [x] `Residual Multiplier` 继续保持现有范围 `1.00–2.00`、步进 `0.05`、默认 `1.00`；r2 不改变其兼容语义。
- [x] 四个新倍率范围均为 `0.00–2.00`，native 层、shader 常量和 UI 元数据使用同一 clamp；NaN/Inf 或越界导入值必须回退/钳制，不能进入 GPU 常量。
- [x] `Adjust Input Resolution` 关闭时不执行残差合成，四个新参数即使存在于 JSON 中也不影响画面。
- [x] `Adjust Input Resolution` 开启且比例为 `100%` 时仍执行全部新控制，与现有 Residual Multiplier 合同一致。
- [x] DLSSNR backend 失效、采用原图回退但仍启用分辨率调整时，残差为零；任何新参数组合都不得凭空改变画面。
