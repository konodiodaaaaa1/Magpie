# v0.6.5 r2 fix5 TODO：DLSSNR Residual 明暗分类修正

基线：`0.6.5` 分支工作树。2026-09-05 已纳入 `0.6.5 r5 local` 实现：完整 RGB 按线性 Rec.709 亮度差硬分类，随后分别调节 HSL 差值；全一默认和零残差保留快速路径。生产 shader 严格编译通过，实机画面验证按用户要求留给用户。下文保留原始方案供核对。

## 问题结论

- DLSSNR Residual 当前是 `denoisedOutput - input` 的零中心有符号浮点差值，内部不存在 `0–127 / 128 / 129–255` 的中性灰分段。
- 中性灰编码只适合差值诊断图；不能用作正式 Residual 合成模型。
- 当前按 RGB 分量分别执行 `min(residual, 0)` 与 `max(residual, 0)`，同一像素可能同时进入暗部和亮部控制，不等价于判断该像素整体变暗或变亮。
- 暂时保留以下四个暴露参数名称：
  - `Residual Saturation Multiplier`
  - `Residual Lightness Multiplier`
  - `Shadow / Structure Control`
  - `Reflection/Glow Control`

## 实现方案

### 1. 保留零中心浮点 Residual

- [ ] 继续使用有符号浮点 Residual，不转换为 8-bit 中性灰编码。
- [ ] 保持基础差值方向为 `DLSSNR output - input`：负值表示对应通道降低，正值表示对应通道提高。
- [ ] 先应用现有 `Residual Multiplier`，得到 `scaledResidual`。

```hlsl
float3 scaledResidual = residual * ResidualMultiplier;
float3 referenceOutput = saturate(input + scaledResidual);
```

### 2. 使用线性亮度差判断整像素方向

- [ ] 将 `input` 与 `referenceOutput` 转换到相同的线性 RGB 空间。
- [ ] 使用相同的 Rec.709 亮度权重计算分类差值。

```hlsl
float deltaY =
    Luminance(ToLinear(referenceOutput)) -
    Luminance(ToLinear(input));
```

- [ ] `deltaY < 0` 时使用 `Shadow / Structure Control`。
- [ ] `deltaY > 0` 时使用 `Reflection/Glow Control`。
- [ ] `deltaY == 0` 时方向倍率为 `1.0`。
- [ ] 不增加柔性死区、阈值、`smoothstep` 或跨零渐变；严格按零点硬分类。
- [ ] 分类结果作用于完整 RGB Residual，不再按 RGB 通道分别选择两个倍率。

```hlsl
float directionalMultiplier = deltaY < 0.0
    ? ShadowStructureControl
    : (deltaY > 0.0 ? ReflectionGlowControl : 1.0);

float3 controlledResidual = scaledResidual * directionalMultiplier;
float3 candidateOutput = saturate(input + controlledResidual);
```

### 3. 最后缩放 HSL 差值

- [ ] 在方向倍率合成后，将 `input` 与 `candidateOutput` 转换为 HSL。
- [ ] `Residual Saturation Multiplier` 只缩放候选输出相对输入的 Saturation 差值。
- [ ] `Residual Lightness Multiplier` 只缩放候选输出相对输入的 Lightness 差值。
- [ ] HSL 调节继续在当前 SDR RGB 表示中完成；明暗分类单独使用线性 RGB 亮度，不混用两个颜色空间的语义。

```hlsl
float3 inputHSL = RGBToHSL(input);
float3 candidateHSL = RGBToHSL(candidateOutput);

candidateHSL.y = saturate(inputHSL.y +
    (candidateHSL.y - inputHSL.y) * ResidualSaturationMultiplier);
candidateHSL.z = saturate(inputHSL.z +
    (candidateHSL.z - inputHSL.z) * ResidualLightnessMultiplier);

float3 finalOutput = HSLToRGB(candidateHSL);
```

### 4. 避免循环分类

- [ ] Shadow/Glow 分类只使用应用方向控制前的 `referenceOutput`，不得使用 `finalOutput` 反向决定本次方向倍率。
- [ ] 如需诊断用户最终看到的实际明暗变化，可额外计算 `Luminance(finalOutput) - Luminance(input)`，但该值不得参与控制分支。
- [ ] 参数变化不能反向切换自己的分类依据，避免形成循环依赖。

### 5. 默认兼容与验证

- [ ] 四个精细控制参数均为 `1.0` 时保留快速路径，确保默认输出与当前 `Residual Multiplier` 路径一致。
- [ ] 验证纯负、纯正、混合 RGB 差值；混合通道像素每次只能选择一个方向倍率。
- [ ] 验证完全零差值不受 Shadow/Glow 参数影响。
- [ ] 验证 `Residual Saturation Multiplier = 0/1/2` 与 `Residual Lightness Multiplier = 0/1/2` 的语义分别正确且未接反。
- [ ] 检查高对比边缘和 Lanczos 重采样振铃区域，确认硬分类没有逐通道色偏。
- [ ] 后续实施时完成 Release x64 构建、`git diff --check` 和目标 GPU 实机对比；本轮不执行这些步骤。

## 完成定义

- Shadow/Glow 的选择依据是整像素线性亮度变化，而不是单个 RGB 分量的正负。
- 一个像素只应用一个方向倍率；完整 RGB Residual 的方向保持一致。
- 分类严格以 `deltaY = 0` 为边界，不包含柔性死区。
- Saturation 与 Lightness 继续分别缩放最终候选相对输入的 HSL 差值。
- 默认参数为 `1.0` 时不改变现有默认画面。
