# 0.6.5 r8 实施记录

日期：2026-09-05。基线：当前 r7 fix 工作树；版本 `0.6.5-r8-local`。用户授权实施，运行与画质测试由用户负责，不使用 computer-use。

本记录的构建哈希属于 r8 首次交付。后续 NVOF 最高质量（2S）补充及覆盖部署结果见 [r8 NVOF 2S 实施记录](20260905-v0.6.5-r8-nvof-2s.md)。

## 已确认的范围

1. 修复光流提供者停用后每帧 reset，以及尺寸适配丢失 reset 元信息。
2. 统一实时参数的目标值／已生效值，修复自动重建恢复旧参数和失败后控件状态不明。
3. AMD OF 增量构建、重复字节码生成清理。
4. 限定效果器专用参数显隐规则的作用域，两套 UI 共用。
5. 为 SR 提供 AMD OF／NVOF 来源及档位；合并 DLSS SR、FSR 2/3/4、XeSS SR 的实验变体。

用户确认：每种 SR 只保留一个入口，不使用光流作为参数选项；删除 metadata-only jitter；移除内置光流，旧 FSR／XeSS Optical Flow 改用 AMD OF 质量档。

## 参数与迁移

| 效果器 | 统一内部标识 | 新建时默认来源 |
| --- | --- | --- |
| DLSS SR | `DLSS\DLSS_SR` | NVOF 均衡 |
| FSR 2 | `FSR2\FSR2_SR` | 不使用 |
| FSR 3 | `FSR3\FSR3_SR` | 不使用 |
| FSR 4 | `FSR4\FSR4_SR` | 不使用 |
| XeSS SR | `XeSS\XeSS_SR` | 不使用 |

统一参数：`opticalFlowMethod` 为 0 None、1 AMD OF、2 NVOF；`amdOpticalFlowMode` 为 0 性能、1 质量；`nvidiaOpticalFlowQuality` 为 1 性能、2 均衡、3 质量、4 高质量。只有选中来源的质量控件显示。三项均为 Restart；修改不会在后台静默创建新提供者。

- `*_ZeroMV` / `*_ZeroMV_Jitter` → 同家族 `*_SR`，来源 None。
- FSR 2/3/4、XeSS `*_OpticalFlow` → 同家族 `*_SR`，来源 AMD OF、质量 1。
- `DLSS\DLSS_OpticalFlow` → `DLSS\DLSS_SR`，NVOF、质量 2。
- 原 `DLSS\DLSS_SR` 的 `motionVectorQuality=0` → None；1～4 → 同档位 NVOF。旧布尔开关先按原有迁移规则处理。
- 迁移在配置读取和效果组导入的共同路径执行；只匹配明确的内置 ID，不按后缀修改第三方效果。保留组名、顺序、缩放方式和比例。废弃参数随后清除。
- 不合并或删除用户自建效果组；不修改默认效果组的其他参数。XeSSFG 的内部 ID 本轮保持兼容，显示名此前已移除 Zero MV。

## 实现边界

光流 provider 使用独立的降级状态记录：失败首帧和恢复首帧通知 reset，稳定零向量帧保留正常 frameId。三次失败后的有限停止策略不变。外部 Resize／LongPause 等明确历史失效事件仍通知 reset。适配为其他尺寸时，即使复用零纹理，也沿用提供者自己的元信息；不能直接用通用 Zero 元信息覆盖它。

FSR 2/3/4、XeSS SR 的消费路径从固定内置申请改为显式 `MotionVectorRequest`，等待发布的 GPU fence 后读取或复制共享向量。深度、反应遮罩等 SDK 合同资源继续保留。共享池仍只初始化选定来源的一套实际档位。

参数会话持有已生效值和已提交目标值；后端只有成功应用才更新已生效快照。自动拆除 Renderer 后先取得最终快照，再重建效果组，不顺带应用 Restart 项。另修复 `Start(std::move(_options))` 对自身移动赋值的风险。显式应用并重启使用用户目标值。

运行参数面板显示与已生效值不同的项及其当前值，保存状态与 GPU 应用状态分开。主窗口已打开的参数页收到配置变更通知；主窗口修改也会投递到当前匹配会话，Live 项走原有合并邮箱，Restart 项保留为目标值。保留 r5 的自动保存、变更合并、配置冲突保护及错误详情，不恢复单独的保存按钮。

AMD OF 指纹覆盖生成脚本／编译选项、SDK shader/include、DXC 及相邻编译运行库。输出缺失或被改动时重建；同内容不重写 header。7 个 pass 各自保存两份 HDR 选项的 FP32 字节码，wave64/16bit 名称只作 SDK 接口别名，不宣称增加了这些优化变体。Clean 跟踪生成输出。

SR 后端类名改为 `FSR2Upscaler`、`FSR3Upscaler`、`XeSSUpscaler`。既有构建开关 `EnableFSR2ZeroMV` 等保留，避免让本地 `.props.user` 的配置失效；这些是构建兼容名称，不再对应独立效果器入口。

## 用户验收重点

- 旧组导入后入口和来源是否符合上表；单 SR、NR→SR→FG 串联能否保持同来源共享。
- 光流降级后 SR／FG 是否稳定，重新启用组后能否正常恢复。
- Live 参数修改后切换全屏／窗口模式、自动重建，画面和参数值是否一致；Restart 目标是否仍待应用。
- 两处参数页同步、失败提示、自动保存、170ms 双击恢复默认值，以及 r7 的下拉框外部点击收起是否正常。

AMD 场景切换检测信息向共享池传递、滑条临时文本输入的单位问题、HDR，未包含在本轮授权的四项修复中。
