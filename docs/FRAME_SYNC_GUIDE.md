# Front Edge Sync（0.6.5）

主页和工具栏的参数面板顶部均提供「帧同步」，位于所有效果器之前。Front Edge Sync 默认开启，目标帧率默认 60 FPS。VRR 入口暂时隐藏，运行时停用。开关和目标 FPS 自动保存，两处界面同步显示；**点击参数面板的“应用并重新启用”后生效**，也可手动停用再启用效果组，不需要重启 Magpie。两项标记为“重启”；未应用的修改不会改变当前运行的帧率过滤器和 FG 节奏。旧配置没有这些字段时采用上述默认值；用户保存的 Front Edge Sync 选择不会在以后启动时被强制覆盖。

## Front Edge Sync 怎么用

Front Edge Sync 稳定的是 Magpie 可控制的帧提交边界。它只控制 Magpie，源程序仍需使用自己的限帧或 RTSS。它不是两个进程之间的逐帧同步，也不是扫描线同步。

目标帧率的单位是基础 FPS：

| 设置 | 无 FG | 2 倍 FG | 3 倍 FG |
| --- | --- | --- | --- |
| 手动 80 FPS | 目标提交 80 FPS | 基础输入 80 FPS，名义输出 160 FPS | 基础输入 80 FPS，名义输出 240 FPS |
| 自动，显示器 240 Hz，无其他上限 | 240 FPS | 基础输入 120 FPS | 基础输入 80 FPS |

- 0：按输出显示器刷新率设置目标，FG 按倍率折算基础帧率。无法读取刷新率时按 60 Hz 处理。
- 手动范围 1–1000 FPS，支持小数；已有应用配置或捕获后端的更低上限仍然生效。
- 目标是上限和调度参考。源程序、捕获或效果处理跟不上时，实际帧率会更低；不会重复把旧画面送进 NR／FG 来凑数字。
- 工具栏中的 FG 总／真实帧率继续按呈现记录与 SDK 报告统计，不直接把设置值乘倍率显示。
- 低目标帧率会使同画面内的工具栏和软件光标更新变慢。同步等待也可能增加输入延迟。

对于此前「源程序与 Magpie 都锁 80 FPS、DLSSNR、无 FG」的场景：源程序继续锁 80，主页开启 Front Edge Sync 并设为 80。先取消 RTSS 对 **Magpie 自身**的限帧，避免套两层控制；源程序的 RTSS 配置可以保留。本轮可比较同步开关的效果，VRR 暂不可用。

## FrameRate Filter 的帧率来源

FrameRate Filter 新增「帧率模式」，默认「基于 Front Edge Sync」：

| Front Edge Sync 开关 | 帧率模式 | 自定义滑条 | 实际限帧来源 |
| --- | --- | --- | --- |
| 开启 | 固定为「基于 Front Edge Sync」，禁止修改 | 禁用 | 主页目标基础帧率；不会再叠加效果器的自定义上限 |
| 关闭 | 基于 Front Edge Sync | 禁用 | 读取主页保存的目标，使用普通限帧；不会隐式开启同步 |
| 关闭 | 自定义 | 可编辑，1–240 FPS | 效果器自己的自定义帧率 |

两处参数页采用相同规则。自定义数值和已选择的自定义模式会保留；开启同步期间显示并使用跟随模式，关闭后恢复此前的选择。旧效果器配置缺少新模式字段时，采用「基于 Front Edge Sync」，仍保留原有自定义数值。

跟随模式中的 0 仍然按显示器刷新率和 FG 倍率折算，跨显示器后重新计算。关闭同步时切换效果器模式或修改自定义滑条可实时生效；主页同步开关和目标仍在重新启用效果组后生效。旧主页配置中已保存的 0（自动）不会被新的 60 FPS 默认值覆盖。

## 各条管线如何处理

| 管线 | Front Edge Sync 的控制位置 | 生成帧输出 |
| --- | --- | --- |
| 无 FG，普通 DXGI 呈现 | 前端先准备图像，在 Present 开始前等待截止时间；内容、工具栏、软件光标共用提交节奏 | 不适用 |
| DLSSFG | 前面的效果处理完成后，保留这一帧的颜色、参考原图与光流，等待后送入 DLSSFG | 保留原有有界队列、生成帧／真实帧顺序和输出节奏 |
| XeSSFG／XeSS MFG | 把基础帧率按倍率换算为 XeLL 的输出帧率目标，由 xellSleep 在补帧前控制输入 | 由 XeSS 代理交换链与 SDK 调度 |

普通路径和 XeSS 路径只允许一个尚未被呈现消费的共享结果，消费后才接受下一张输入进入效果处理。DLSSFG 在等待输入时不再捕获下一帧覆盖颜色或光流。这样避免为了前端限帧而在后端继续大量计算并丢弃结果。

Magpie 自有等待使用可被消息中断的定时器，等待期间不持有共享纹理锁；长卡顿后重新确定节奏，不积攒欠帧后连续补交。无 FG 时保留原有的最小帧率更新并限制在目标以内，支持依赖帧计数的动态效果；NR 对同一输入保留缓存复用。XeSS 使用 SDK 自身的低延迟等待，不在代理 Present 前后再添加一个 Magpie 输出限帧器。SDK 等待及 GPU／驱动等待不属于可由 Magpie 完全控制的时间。

普通 DXGI 路径开启同步后，将交换链最大帧延迟设为 1；关闭时恢复原有队列设置。DLSSFG 保持已有的最大帧延迟 1。缓冲数量与实际延迟不是同一个指标。

窗口移动／调整大小时允许采用原有呈现方式，结束后重新建立同步节奏。无 FG 时，如果应用配置禁用了 DirectFlip，或构建使用了替代的 Composition Swapchain 呈现器，r10 不启用此 DXGI 提交控制。基准测试模式也不使用 Front Edge Sync。运行日志会记录请求值、实际模式和目标。

## VRR 暂缓

本轮暂时隐藏 VRR（可变刷新率）设置并停用其呈现请求。旧配置的 VRR 字段保留兼容，但即使保存为开启，也不会在运行时启用；不需要用户手动修改配置。关联的全屏焦点实验已撤回，继续让源窗口保持前台焦点。

相关 DXGI 代码和翻译保留，待后续研究确认显示器变频与输入兼容性后再考虑开放。Front Edge Sync、FG 调度与 GPU **REALTIME** 优先级保留。本次停用的是 Magpie 的显式 VRR 请求，不修改显示器或驱动设置。

## 本轮呈现等待优化

当普通 DXGI 或 XeSS 交换链暂时无容量时，外层消息循环现在同时等待容量事件和输入消息，减少容量已经可用却仍要等待下一次轮询的情况。已取得的容量令牌会保留给下一次提交，避免重复等待。Front Edge Sync 截止时间仍优先，XeLL 等待与 FG 输出调度保留；这不代表端到端延迟固定减少某个数值。r9 的捕获连续性、共享图像同步及重复叠加层呈现抑制继续保留。

## 验证范围与已知边界

已完成 Release x64 编译、CPU 时钟与等待检查、配置／资源和打包检查。没有启动 Magpie，也没有做 GUI／GPU 测试；帧时间改善与 FG 画面质量由用户测试，VRR 暂缓。

建议保持同场景、同效果参数和同目标 FPS，分别比较同步开／关；FG 另测 DLSSFG 和 XeSSFG。切屏、拖动性能分析器、修改帧率过滤器、停止再启用效果组也需要实机覆盖。提交间隔稳定并不保证物理显示间隔完全一致，源捕获真正缺失的帧仍会造成停顿。
